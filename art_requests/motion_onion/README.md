# 洋葱皮补帧流程

给小怪和 Boss 补中间帧时，保证身体大小、站位和原画一致。工具是 `tools/motion_onion.py`，质检门槛是 `tools/audit_motion_scale_consistency.py`。

## 为什么不用 v8 的做法

v8 让 AI 在 6×4 的缩略图板上一次画 24 帧，两张端点图各自缩放后放进格子，生成后再按"两端剪影高度的平均值"去猜每帧该缩放多少。伏低、蓄力的帧剪影矮，于是被放大；倒地动作里站起来的那帧剪影高，于是被缩小。#580 的 v8 层里，有 222 帧的主体面积超出相邻帧的 0.67–1.5 倍。

手绘动画不会出现这种问题：每一帧都画在同一块画布、同一个比例上，叠着前后帧的洋葱皮画。这个流程把同样的参照系交给 AI，**大小和位置由程序决定，AI 只负责画**。

## 步骤

1. **出画布** `prepare --kind <角色> [--animation <动作>]`
   - 每张 1536×1024，3×2 共 6 格。每格都是这个角色的运行时画布，按固定倍率 K 放大。同一角色的所有画布共用同一个 K，记录在 `jobs/<角色>.json` 里。
   - 格子里用蓝色画前一姿势、橙色画后一姿势，都是半透明洋葱皮，按运行时的真实位置摆放；两端都着地时再画一条地面线。
   - 四角各有一个绿色定位方块。
   - 同时输出一张身份参考图（前一姿势的全彩版），和洋葱皮画布一起交给 image_gen。提示词写在任务的 `prompt` 字段里。
2. **交付** `deliver --job <任务> --image <生成图>`
   - 先找四角的绿色方块，算出整张图被平移、缩放了多少，再映射回参考画布。只允许整体平移和等比缩放，出现拉伸就整张拒收。
   - 每个人物按 `(画布坐标 − 格子原点) / K` 换算回运行时坐标，**不再逐帧估算缩放**。
   - 每帧自动质检，任何一项不合格都拒收：
     - 主体面积不在两端的 1/1.5–1.5 倍之内；
     - 两端站在同一地面时，脚离地面线超过 5%；
     - 身体中心跑出两端范围之外；
     - 颜色偏差过大；
     - 越出格子或越出运行时画布；
     - 照抄某一端点的姿势。
   - 每次生成的原图、提示词和逐帧结果都记在任务的 `attempts` 里。合格帧保存到 `accepted/<角色>/`，并记录 SHA-256。
3. **只重画不合格的帧** `retry --kind <角色>`：把被拒的那几个过渡重新排成新画布，然后回到第 2 步。不合格的帧不手工修。
4. **构建层** `build --kind <角色> [--over motion_v8_manifest.json]`，生成 `motion_onion_manifest.json` 和 `motion_onion_NN.png`：
   - **插入模式**（默认）：以原始 v7／Boss 层为底。一条动画的每个过渡都有合格帧时，才在每个旧姿势后插入一帧并把 fps 翻倍，时长不变；没补齐的动画保持原样。
   - **替换模式**：以 v8 层为底，只把重画过的中间帧换掉，其余 v8 帧不动。适合只修 #580 中不合格的那部分。
5. **翻页检查** `preview --kind <角色> --animation <动作>`：输出循环 GIF 和逐帧条图，新画的帧用橙色框标出。自动质检之后，还需要人看一遍。

运行时优先读取 `motion_onion_manifest.json`，见 `godot/scripts/hand_drawn_assets.gd`。

## 门槛与 CI

`npm run test:motion-onion` 包括三部分，也在 `.github/workflows/motion-scale-consistency.yml` 里运行：

- **流程往返测试**：用一个模拟生成器把整张图平移、缩放，验证配准误差不超过 2px，并验证放大、缺标记、拉伸、越界、照抄这几种情况都会被拒；
- **`motion_onion.py check`**：已提交的新层必须能逐字节重建；
- **比例门槛**：生成补帧层（`motion_onion_*`、`motion_v8_*`）里，任何一帧的主体面积超出相邻两帧 0.67–1.5 倍即失败。较早的手工整段层只报告不拦截；目前 main 上有 26 处离群，例如水蛭飞扑这种身体本来就会拉长的动作。

这些检查只保证尺寸、位置和颜色。动作是否顺、是否像同一个角色，仍要靠翻页预览和实际游玩判断。
