## 2. 对话状态机统一规范

### 2.1 状态定义与优先级

| 状态 | 触发条件 | 条数 | 说明 |
|---|---|---|---|
| `first_meet` | `npc_met_<id>` 未置位 | 3–4 | 播完整轮后置位；前 3 条兼容现行 `dialogue[3]` 兜底 |
| `repeat` | 无更高态命中 | 2–3 | 默认循环池 |
| `after_ability` | `inventory_counts` 含 `dialogue_meta.ability_ref` | 2 | 每个 NPC 绑定一项相关能力 |
| `after_boss` | `story_flags` 含 `boss_down_<chapter_id>` | 2 | 建议在章 Boss `died` 信号处置位 |
| `sidequest_done`（可选扩展态） | `story_flags` 含 `dialogue_meta.quest_flag` | 2–3 | 仅支线 NPC 持有 |
| `late_game` | 背包含 `dialogue_meta.testimony_ref`（testimony_01–06） | 2 | 拿到该区证词后 |
| `true_ending_branch` | `story_flags` 含 `true_ending_testimony_complete`（六证词齐） | 2–3 | 真结局线；沿用蓝图第 11 节 flag 名 |

选择优先级（高→低）：`first_meet`（仅首次）→ `true_ending_branch` → `late_game` → `sidequest_done` → `after_boss` → `after_ability` → `repeat`。同态内仍按现行 `dialogue_index % size` 循环。

### 2.3 字段迁移说明（三步，均向后兼容）

1. **第 0 步（零代码上线）**：把各 NPC `story_dialogue.first_meet` 前 3 条回填现有 `dialogue` 数组——本文档的 `dialogue` 字段已是修订后版本（病句已清洗），直接覆盖即可，`_talk_to_npc` 无需改动。
2. **第 1 步（状态机接线）**：`main_level.gd` 的 `_talk_to_npc` 前插入状态解析（约 20 行）：

```gdscript
func _resolve_npc_lines(meta: Dictionary) -> Array:
    var sd: Dictionary = meta.get("story_dialogue", {})
    if sd.is_empty():
        return meta.get("dialogue", [])
    var mid: String = "npc_met_%s" % meta.get("id", "")
    if not story_flags.has(mid):
        story_flags[mid] = true
        return sd.get("first_meet", meta.get("dialogue", []))
    for state in ["true_ending_branch", "late_game", "sidequest_done", "after_boss", "after_ability"]:
        if sd.has(state) and _dialogue_state_ok(state, meta):
            return sd[state]
    return sd.get("repeat", meta.get("dialogue", []))
```

   `_dialogue_state_ok` 按 2.1 的条件查 `story_flags` / `inventory_counts`。`story_flags` 字典建议挂在存档数据上，与 `chapters/*.json` 已备好的 `story_beats[].story_flag` 同名共用（如 `beat_ch02_oath_plate` 可直接当 `boss_down_ch02` 的同义 flag 使用，二选一，不要双轨）。
3. **第 2 步（离场系统）**：`dialogue_meta.leave` 描述离场/迁居/死亡；关卡加载时若 `leave.condition` 满足，则该 NPC 不再生成于原位，改按第 14 节《迁居与告别总表》生成于新位置或替换为遗留物拾取点。

## 3. 台词写作规范

### 3.1 一句话节奏（三句模）

本作台词的标点签名是**分号**——模拟钟摆的两拍。单条台词 ≤ 42 字，一条只装「一个信息点 + 一个情绪点」。

| 句模 | 结构 | 范例（既有 canon） |
|---|---|---|
| 甲·工具句 | 前半教操作，后半给代价或世界观 | 左键斩击，右键缝回一口气；绯线救命，也会把贪心的人勒住。 |
| 乙·翻转句 | 前半立常识，分号后翻掉它 | 我压住黑潮，也压住了每个求救声；久了以后，两者听起来一样。 |
| 丙·留白句 | 短句顿挫，破折号收口，留半拍 | 短句——安全。长句——会被接走。就这样。 |

### 3.2 比喻域约束

NPC 只准使用**出生区比喻域 + 亲身旅行过的区域**的意象；游走 NPC 可以混域——「见过世面」正是他们的语感标记。

| 区域 | 允许意象 | 示例禁忌 |
|---|---|---|
| ch1 苔钟庭 | 苔、青铜、绿锈、钟摆、回声、庭院 | 不得提「盐」「花粉」（没去过） |
| ch2 铸雨渠 | 雨、铁、锤、水声、锈、名字沉底 | 不得用「灯影」比喻 |
| ch3 盐白档案馆 | 盐、纸、墨、空白、结晶、索引、封蜡 | 不得用「藤蔓」比喻 |
| ch4 断弦温室 | 弦、歌、藤、玻璃、花粉、修剪、病房 | 不得用「军令」比喻 |
| ch5 黑曜巡礼路 | 灯、影、黑曜石、队列、命令、旗、坟 | 不得用「书页」比喻 |
| ch6 寂冠核心 | 白金、无声、共鸣、签名、清单、钟舌 | 意象最克制，形容词减半 |
| 深井黑潮 | 墨、井、沉、哭声、绯线 | 仅黑潮童声与绯线低语可用 |

### 3.3 禁用词表

- **机制裸词**：HP / MP / 等级 / 玩家 / 存档 / 读档 / 掉落 / 刷怪。教学台词允许按键名（左键 / E / F）与叙事化别名：地图＝苔光镜，存档点＝钟龛，货币＝松脂碎片，快旅＝钟骨长梯。
- **现代口语与网络语**：加油、没问题、OK、拿捏、破防、666 等一律禁止。
- **空洞套话**：「命运」「宿命」每章至多出现 1 次；禁止「黑暗的力量」式泛指。
- **敬语「您」**：仅后门司铃人与锈枪骑士两个礼仪角色可用。
- **语气词「啦 / 呀 / 哦 / 嘛」**：仅「童声类」角色持证使用（管渠童子、黑潮童声、唱铃朝圣者丁当、断弦歌者的哼唱）。
- 禁止直接玩《丝之歌》梗（角色名、地名、台词化用需完全本地化）。

## 10. 跨区游走 NPC 总则

对标丝之歌的三类循环角色：**Shakra**（绘图师，帐篷随进度迁移全图）、**Sherma**（朝圣者，一路唱着祷歌走完自己的朝圣路，可救援）、**Garmond & Zaza**（骑士，多区并肩作战，有自己的战报）。三位游走 NPC 的共同规则：

1. **站点驻留**：每人一张路线表，站点全部使用现有房间 id；「当前站点」由 `story_flags` 推进（到访下一站的条件满足即迁移，玩家回访旧站只见留痕，不见真身——重逢感来自「他也在赶路」）。
2. **游走 NPC 允许混用比喻域**——见过世面是他们的语感标记（3.2 节例外条款）。
3. **每人一条支线 + 一件独有奖励 + 三结局各有戏份**；奖励效果为数据侧建议，落地时按护符系统实作。
4. 数据结构与常驻 NPC 相同，`story_dialogue` 的状态键改为站点键（`station_<room_id>`），另保留 `sidequest_done / true_ending_branch` 两个通用键。
