# 第一组十间能力回访工房

承接六区实体通道网络 PR #82 / f6b1d42ff3d64df8cfda034e9c03fbdae95d0aec。此批只重构下面十间旧区回访房，CH05 灯影相位练习房和其余九间保持各自现有布局。

| 能力 | 两间房 | 实际路线 |
|---|---|---|
| 绯线冲刺 | 排水计时闸、淤泥排压室 | 动作开闸后离开低梁，再穿行错层落脚台、登上物资架 |
| 丝壁攀附 | 纺线检修仓、泵房上检修舱 | 贴住竖面减速，蹬墙跳回承接台，再跨过竖面或双塔登上证物台 |
| 回声钩索 | 钟骨吊运台、运书吊篮仓 | 原近侧吊环操作闩门，新增高位吊环用于牵引和上层落台 |
| 双线跃 | 钟冠双线仓、双层水位记录室 | 地面起跳后明确松开，再空中二跳抵达高台；高差分别为180/205px |
| 钟壳格挡 | 钟髓封蜡室、旧铸工证物柜 | 钟壳脉冲开封蜡闩，再沿两层证物柜取回记录和物资 |

## 配置与生成

十套配方写入 world_routes.json 的 workshop_layouts，以 movement_group_one 标记。每间都有独立 archetype、真实碰撞平台、脚底坐标 route_steps 和奖励平台；十套平台排列均不同。生成器将相对路线转成生产房间绝对位置，恢复六处既有战斗练习元数据；两间钩索房额外生成高位吊环。两轮重生成必须保持文件完全一致。

保持原房间外壳、入口、能力动作闩与永久开闩键。所有落脚台下方仍有原底层维护道；失败可重新起跳，取奖后能落回入口。每间原有记录、碎钱数量和奖励身份不变；源区和工房间的成对入口不变。按对象身份比较，生成数据的改动均属于这十间房，没有其它房间/门户/能力闩被改写。

这些房间提供能力操作和回访路线，不声称每一块台都只能由一种技巧抵达；动作闩仍负责永久能力要求。普通跳跃不够抵达两间双线跃房的奖励层。攀壁房的承接台为单向台，允许向上通过并接住蹬墙后的落点。

## 运行验证

ability_workshop_route_validation.gd 接入原 world_upgrade 正式入口。门前移动、实际能力输入、平台移动、两件奖励、返回原平台和再次进入保留原业务检查；专项还记录门开启后的攀壁、钩索与二跳事件，确认没有借助额外双跳能力。没有修改角色速度、跳跃高度或碰撞尺寸。

十间分别在领奖和返回后销毁 World，从真实磁盘存档重新实例化：核对原地区、永久闩、唯一记录与钱包、两件已收集身份，再以明确的源区定位夹具重入工房，检查闩门实际开启、奖励不重生、资源不重复以及出口有效。这是组件级取得/重启验证，不是从钟龛自然走完原地区的全流程证明。

每间路线成功抵达后强制绘制一帧并保存实际 World 截图；批量 suite 其余帧仍沿用既有不自动绘制方式。CI 上传十张截图和回归日志。截图在取奖过程生成，可能包含原有瞬时拾取提示与动作特效。

结构契约检查十间身份、五能力各两间、十种平台排列、脚底目标的实际支撑/净空、原奖励平台与双跳高度；7项正反测试包含重复配方、缺步骤、悬空落点、非法动作、重复 archetype 和错误奖励平台。两轮生成一致性是独立检查。

首轮实走发现短按跳跃提前切低跳高、第二吊环牵引线贴台和蹬墙回落没有承接台。已调整真实按键节拍、吊环和落台，保留失败日志；后续10间路线均分别通过。新增布尔类型推断错误也已修正后复验，不将中间错误或超时计为通过。最终 Godot 4.6.1 / llvmpipe：world_upgrade **596/0**（完整20间工房、10间新路线及逐间磁盘重启）；ability_movement 通过，upgrade_integration **30/0**，obsidian_experience **197/0**，CH06 工房 **21/0**，路线权限 **553/0**。通道网络 **140/0**、世界地图 **671/0** 与购图补绘 **4143/0** 兼容回归通过。7项布局契约单测、npm/campaign、两轮重生成一致性及双轮严格资源导入通过；52个变更对象均属于本组，无其它房间/门户/闩门被改写。完整远端 CI 另按正式 PR 提交判断。

本批不改主线能力获取，不计自然六区带伤通关、陌生玩家理解或整包性能验收。剩余九间工房、跨区获取到回访的完整自然流程和长期稳定继续留在台账。
