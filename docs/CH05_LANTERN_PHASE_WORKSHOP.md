# CH05 灯影相位练习工房

`upgrade_lantern_phase_3` 是 pilgrim camp 的可选练习支路。工房保留原房间坐标、地图矩形、相位闩、双向入口和两项奖励。开启下层闩门后，玩家先跳上检修低台，再登上灯廊高台取得操作手册与 70 松脂；从高台落回地面，按互动键返回营地。

布局只针对这一个房间。`tools/build_world_upgrade.py` 从 `world_routes.json` 的 `workshop_layouts` 生成两块平台，并把既有奖励放在高台。其余 19 个能力工房沿用原布局和移动组合。

## PR #72 后的验收收口（2026-10-15）

基线：[PR #72](https://github.com/superman2003/Crimson-Thread-Pilgrimage/pull/72)，`04cc57fdfe5c2b81a85d1b997f1ca0b1f73892ce`。原 `obsidian_experience` 为 176 项、11 失败。本批定位并修正测试夹具；实际双层路线能够用普通单跳走通，生成器与世界数据均无需改动。

### 两类根因

- 四项坐标断言把 JSON 读出的浮点数组与整型数组直接比较，错误拒绝了相同数值。现在逐项检查数组长度、数字类型、有限值和精确数值，仍拒绝改动坐标、缺失坐标、字符串和 NaN。
- 原移动助手在同一物理输入帧释放并重新按下跳跃。生产 Player 同时看到按下/释放边沿，跳跃裁剪压短了下一跳；角色随后走到上层平台下方，无法完成攀登和领奖。助手现在为释放留出两个实际物理/处理帧；目标改为平台脚底坐标，落地高度从 45px 容差收紧到 4px。平地行走与回落不主动跳跃。

反向验证保留全部新坐标断言，只移除释放等待：上层攀登及后续奖励/出口共 15 项失败；恢复后通过。该对照没有修改任何关卡几何、伤害或 Player 物理。

### 实际验证链路

使用生产 World、Player、相位闩、平台和拾取器。入口与刚取得灯影相位是预置夹具，之后全部路线使用生产移动输入：

1. 检查未解锁双跳/攀墙，正常伤害保持开启；移动靠近闩门，并向关闭的闩门行走确认实体阻挡。
2. 实际灯影相位输入消耗能量，打开闩门并写入永久动作解锁标记。
3. 普通单跳依次抵达脚底 y=490 的低台与 y=380 的高台；助手不调用双跳、冲刺、钩索或角色重定位。
4. 穿过高台领取两项奖励，验证操作手册恰好增加 1、松脂恰好增加 70。
5. 实际回落并按互动键退出到营地；再次按互动键回访，检查闩门保持开启、奖励节点不重生、物品与货币不重复增加，再从实际出口返回。

既有 CH05 测试入口继续调用该专项，完成标记、超时与严格错误门禁保持原样。两个脚本在夹具释放前调用既有音频退休服务；在生产宿主清理末尾检查排空，运行时音频未改。

扩展回归另发现原 `world_upgrade_validation.gd` 的 7 项失败：该入口仍只水平行走，无法到达高台奖励。本批为 `upgrade_lantern_phase_3` 增加两级单跳，复用同一移动助手；原 20 工房的奖励、真实存档读回、永久门闩与回访断言全部保留。该补修是本批新增占用文件，已在开工更新中说明。

### 结果与边界

最终 CH05 真实 GL 复验为 **195 项、0 失败**，覆盖原有房间/遭遇与新增工房链路。初步结果为 186 项与 194 项零失败，均保留在本地日志。最终全工房 `world_upgrade` 为 **405 项、0 失败**（补修前 403 项、7 失败）。其它三套相关真实 GL 回归 `ability_movement`、`world_route_access`、`player_state_cleanup` 通过；共 5 套不同相关入口通过，其中部分退出警告保留。

`npm test` 与 `npm run test:campaign` 通过。Godot 4.6.1 / Mesa llvmpipe，恢复模式资源导入两轮通过。早期临时探针缺少资产导入侧文件时出现字体/依赖脚本错误，虽然路线断言通过，也未计为验证成功；完成严格导入后的正式入口才计入通过。

新增清理检查早期曾在独立遭遇结束时提前等待所有流销毁，两次分别报告剩余 6 / 5 个 stream 超时；该位置尚有缓存资源引用，不能用“全部流销毁”描述阶段退出。最终停止该阶段的播放节点，并将排空断言保留在生产宿主清理末尾。未加长排空上限或放宽严格错误检查。CH05 退出仍有 ObjectDB 警告，不能据排空通过声称全部引用或长期稳定已验收。

本地日志保留在工作区 `workshop-logs/`。所有定位/能力预置均为测试夹具；本批不代表从新档自然获得能力、完整六区伤害通关、人工手感或长期稳定验收。远端完整 CI 按最终提交单独判定，不自动合并。
