# feat(browser): 校验进度、失败重试与明确重置

拒绝损坏/非整数解锁数据，保留其他标签页更高进度，写后复核并提供失败重试提示；重置需明确确认且先写盘，保存失败保留当前试玩。

## 使用与验证

通过 `npm start` 打开浏览器试玩。此功能仅影响 `src/` 试玩，不修改 Godot 主工程、存档或现有升级分支。

运行 `node --test tests/browser-03-progress.test.mjs`。测试覆盖正常使用、边界和失效场景；浏览器整合验证另见 PR 描述。没有把试玩验证计入六区 Godot 最终验收。

## 并行协作

以 main 的 `14dbb91` 为基础，使用独立分支。仅包含该功能的模块、main.js 的接入点、专项测试、文档和专用 CI。不修改其他 agent 的分支或公共任务台账。

## 浏览器回归

`tests/browser-features.e2e.mjs` 使用 Playwright/Chromium 启动实际静态服务和模块，按当前分支已有功能运行交互断言。测试仅在响应中附加内部状态观察点，生产脚本不携带测试状态访问口。

安装 Playwright 后运行 `node tests/browser-features.e2e.mjs`。专用 CI 同时运行模型单测与浏览器交互检查，并上传结果和移动端截图。手柄检查使用标准 Gamepad API 模拟，不代替实体手柄验收。

多个功能 PR 携带内容完全一致的工具栏宿主和浏览器测试文件，以便独立运行；它们可被 Git 自动合并，无需依赖另一个未合入 PR。
