# 沿着线索追问

追问是现有交谈中的可选入口。问题只在当前人物与实际已知线索相符时出现；未知问题不会出现在列表、旅记或搜索中。它补充人物对证物的判断，不改变主线、能力、奖励或结局门槛。

每个问题有两段基础回答，以及另一项线索解锁的两段追加回答。追加回答必须重新读完和确认，不会改写已经听过的版本。完整读完并成功保存后，可在行囊的「人物」分类回看；取消、中断或保存失败均不记成已听过。

## 内容约定

- `godot/data/inquiries/*.json` 按文件名排序加载；最多 16 文件、256 问题。
- `requires` 是全部满足的来源，来源只能是实际持有物、已确认环境见闻或生产进度标记。
- `continuation.requires` 是新增证据，不能重复基础条件。
- 问题、回答、手记与来源共同生成版本指纹。内容变化后旧指纹不会被当成新回答已读。
- 证物使用正整数数量；进度与环境标记要求布尔真。冲突的历史结局标记由现有世界叙事裁决。
- 追问没有道具消耗，也没有任务完成或奖励字段。人物说的是对当前证据的理解；不替玩家确认未知历史。

## 验证

`python3 tools/validate_narrative_inquiries.py` 核对人物、拾取物、观察物和生产标记，拒绝重复问题、重复回答和不存在的线索。

`python3 tools/run_narrative_inquiries.py --engine <Godot 4.6.1>` 逐个覆盖基础/追加版本、每项必要条件、未读保护、保存失败回滚、重复确认、过期指纹、人物距离和实际对话窗口。精确 PR head 的 CI 使用同一入口。

## 本轮十批

按系统、六章、支线动机、主角身份和终局后果串接。前一 PR 是后一 PR 的基底，逐项统计独立差异；应按顺序合入。既有 #405 的规范修正、重逢和结局确认界面不在本轮重复实现。

本系统的自动回归属于组件与交互验证。自然游玩中的节奏、全部字号/控制器体验及正式环境演出仍需对应验收，不凭文本增量关闭 N01–N05 最终验收项。
