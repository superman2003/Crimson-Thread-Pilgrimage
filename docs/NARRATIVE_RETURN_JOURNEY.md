# 六城归途：变序证词、支线续接与结局后果

## 基线与占用

基于 `main 2e52403`（已合入 #81）。这是十批计划中的第 7 批剧情升级。本批不编辑另一个工作流占用的通道／工房文件、共享回归运行器、完成标记表或总台账。此文同时作为本批独立交付台账；合并后可由总台账维护者引用。

| 范围 | 实现 |
|---|---|
| 主线变序 | 六份独立证词仍按当前正数量持有量判定；六证词全部 720 种收集排列均可开启改写条件，任何不完整前缀均不可。重鸣／断冠不依赖可选委托。 |
| 场景来源 | 修正旧提示漂移：井喉、沉没档案舱、封存书堆、大树之心、巡礼军墓、冠肋；每份记录绑定实际地区、房间和拾取物 ID，由数据校验核对。 |
| 环境阅读 | 取得证词后，旅记展示对应生产设施、删改痕迹与守门者动机的“场景印证”；四组双证词互证只在双方均已取得时显示。已知但未持有的证词不展示互证。 |
| 六城人物 | 覆盖全部 25 个实际 NPC，提供三种结局各自的本地回应；原有支线、契印／技能和五组一次性奖励保留。根笼囚徒的改写后对白区分是否真正获救。 |
| 结局后支线 | 标记为 `continues_after_ending` 且仍有新标记可提交的状态，优先于结局闲谈；未领的已完成奖励继续使用既有修复入口。完成后重新进入本地结局回应，不循环发任务。 |
| 事务 | 每次对话确认只写一次存档，奖励、心愿板附带奖励、完成／领取标记及构筑解锁一起提交。失败恢复旗标、钱包、构筑、共享世界快照与对话游标，NPC 不迁移。 |
| 结局选择 | 成功写盘后才播放确认、音乐与结局横幅；写盘失败不锁定选择。再次开门显示正式结局文本；已选另一结局时显示中文名称。 |
| 旧档恢复 | 合法 `ending_chosen` 优先；唯一旧 `_done` 标记恢复相应选择与后果；互相冲突的旧标记不擅选结局。清除其它结局所属后果，保留无关任务标记，恢复操作可重复执行。 |
| 旅记 | 结局后果用 NPC 中文名；“已关闭”与“准备中”分开显示，避免已关闭分支继续提示待准备。 |

## 事务与优先级

对白依次解析：已完成却未领取的奖励恢复 → 结局后可继续且确有新进度的状态 → 作者编排的结局／普通状态。查询本身不改进度。字幕未显示完整时不提交；最后一行完成后才生成支线结果。零数量能力键即使被包含在 `inventory.keys()` 中，也不能满足能力门。

运行时在改变旗标和钱包前保存快照；同步构筑解锁但延后应用玩家属性，完成唯一一次存档写入后再显示成功和迁移 NPC。保存失败会恢复快照。对话阅读游标沿用本来仅存于当前驻留会话的设计；重启可能重新读对白，但不会再次发奖。

结局恢复不改变存档版本，也不自动写入尚未确认的结局。互相矛盾的旧选择恢复到未选状态，以便玩家再次明确选择；原存档文件仍由既有存档系统管理。

## 独立专项入口

```bash
python3 tools/validate_world_narrative.py
python3 tools/run_narrative_return_journey.py --engine /path/to/godot --software-gl --log-dir /tmp/narrative-return
```

`run_narrative_return_journey.py` 在自身进程中注册新增套件的完成标记，复用原运行器的隔离存档、超时、退出码、引擎错误及完成标记门禁。原共享文件保持不变。新增 `.github/workflows/narrative-return-journey.yml` 检出精确 PR head，导入资源，并运行六套剧情相关验证与两套构筑／契印集成验证。CI 使用软件 GL；本地已运行的八套使用 headless，不能等同图形验收。

上述运行时验证使用隔离存档、预置证物／能力和定位夹具；结局门由夹具调用正式处理器，不能作为自然抵达、战胜 Boss 或带伤通关证明。场景印证是与拾取房间绑定的旅记阅读说明，不表示已绘制新的刻痕道具。结局影响通过对白、任务、已有 NPC 迁移和旅记体现；六城水位、建筑和敌群并未成为新的结局后模拟。自然新档变序通关、完整结局演出与发布包验收仍属第 10 批。
