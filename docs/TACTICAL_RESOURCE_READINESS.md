# 技能卡片的绯线不足提示

基线：main / 64ec26851e6d664b54d14bf4347cadb4a9d4cfe6。

技能卡片原来只检查冷却，绯线不足时仍显示施放按键。现在读取既有构筑快照里已按契印/构筑修正的 energy_cost，与玩家当前绯线比较：冷却优先显示剩余秒数，随后显示“缺 N”，可负担时恢复当前输入设备的施放按键或“待切换”。休眠槽位仍优先显示原有休眠原因。

不足时图标变暗，并以明确文字解释原因，悬停可读当前绯线与所需消耗；不依赖颜色辨认。资源恢复后下一轮 HUD 刷新立即移除旧提示。判定只供展示，不声称覆盖受击、硬直、地面限制等全部施法条件；实际施放、消耗和冷却仍由既有控制器/构筑事务决定。

新增 tactical_readiness_validation.gd 接入 ui_build_accessibility，11 项生产 HUD 检查使用现有真实 BuildSystem：零绯线、差 1、恰好足够、非激活槽、冷却优先、恢复、修正后消耗与无副作用。Godot 4.6.1 / llvmpipe 的 UI 及反馈无障碍 17/0 通过；build_slots_ui 30/0、input_prompt 36/0 通过；npm/campaign 与最终双轮严格资源导入通过。完整远端 CI 以 PR 最终提交为准。
