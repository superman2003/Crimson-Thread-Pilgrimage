# PR #568：瞬移与试炼落点插值修复

物理插值开启后，瞬移必须同步清理上一位置的绘制历史；普通切换动画则应继续保留移动插值。

本次补上了三个遗漏：

- `boss_combat_style.gd` 的指挥者换位：碰撞扫掠确定最终落点后，立即重置演员的物理插值。预警落点、扫掠约束及后续投射物保持原逻辑。
- `enemy_actor.gd` 的通用闪现：先按原平台边界限制位置，再重置插值。普通 `_set_enemy_animation()` 不再因为调用发生在绘制帧就重置整个演员。
- `main_level.gd` 的试炼开始和死亡重置：恢复角色资源后调用现有 `reset_camera_after_arrival()`，同时重置角色插值、镜头跟随基准及镜头平滑。没有改用会发出复生信号的接口，避免重复触发遭遇重置。

新增 `interpolation_arrival` 正式回归，使用实际敌人技能、试炼处理函数和 Player 落点重置。测试中的几何标记只用于测量渲染位置，不改变生产素材。无关的世界加载和遭遇调度由夹具隔离。

在 Godot 4.6.1、60Hz 物理、240Hz 绘制下测得：

- 修复前，同一套测试 41 项中有 16 项失败。四条瞬移/传送路径的物理位置为 x=800，而插值比例 0.25 时绘制位置为 x=289.5。
- 修复后 41 项全部通过，绘制位置为 x=799.5（16 像素宽标记的像素中心平均值）。普通切换动画仍保留帧间移动插值。

本地验证还包括 Boss 行为、六套技能身份、敌人动作连续性、Boss 试炼、相机焦点、房间镜头稳定性、主角动作连续性和后三章 Boss 命中矩阵，共八套回归通过；`npm test`、分片覆盖检查和导出依赖审计通过。

新套件已加入默认 CI 分片。它需要实际 GL 渲染；仅有无头渲染后端时会明确失败，避免把逻辑位置相同误当作画面没有拖影。

定向执行：

```sh
python tools/run_godot_regressions.py --engine <Godot-4.6.1> --software-gl --suite interpolation_arrival --log-dir <logs>
```

Windows 原生验证使用隔离的不可见桌面运行同一套件，不在用户当前桌面打开游戏窗口。
