# 动作流畅度升级（PR #568）

按 [#569 的 V02 调查](https://github.com/superman2003/Crimson-Thread-Pilgrimage/pull/569) 先处理播放与运动问题，再补关键动作素材。合入 main 的音乐升级，保留全部 33 首音乐及其检查。

## 本次实装

- 敌人显式启用物理插值，出生、复位、回到出生点时清空旧位置历史。
- 蓄力前段正常过渡后停在末帧；收招先保持首帧再快速回正。每段实际帧时长之和仍等于原来的战斗阶段时长，伤害窗口不变。每个敌人独立持有时长资源，不污染共享美术缓存。
- 两帧蓄力循环改为保留最后一张蓄力画，叠加轻微呼吸和震颤；移动攻击循环保留原画，按运动方向施加 4% 拉伸。部分扑击、砸地收招有 100ms 的轻微冲击回弹，绕脚点变形，不移动碰撞体。降低震动设置会同步减弱表现。
- 敌人行走动画跟随本帧实际位移，倍率限制在 0.6–1.4；被地形挡住时暂停踏步。
- 主角按用户选定的“缠线小偶”全面替换：32 个状态均使用小偶，包含上升、下落、转身、各方向攻击和全部技能。空中动作播放一次后保持末帧；低速反向触发可打断的 120ms 视觉转身，游戏朝向与攻击输入立即响应。
- 短足以固定尺寸、距离相位与支撑脚点实现跑动，膝部藏在布摆内，保留重心压低与腾起。碰撞、移动速度、战斗判定和镜头规则保持。

## 美术来源与构建

本批使用内置 image_gen，参考用户选定的小偶概念。原始透明图、实际提示词、引用图片哈希、固定缩放与裁剪区域保存在 [art_requests/thread_doll_motion_v1](../art_requests/thread_doll_motion_v1/README.md)。仅执行透明轮廓隔离、裁剪、统一缩放和定位，没有光流补帧。未选用的人形空中补帧实验保存在本地历史分支，不进入最终发布资源。

`python tools/build_thread_doll.py --check` 复核源文件哈希、172 张独立绘图、注册像素和完整运行清单。动作时长独立冻结在 `runtime_contract.json`；旧人形构建器不能改变默认小偶。`validate_hero_v3.py` 同时检查新身体与保留的历史素材。

## 验证

- 原生 OpenGL：敌人阶段检查覆盖 46 种生物的 114 个普通、精英和 Boss 招式，检查真实帧时长之和、过渡帧不低于 12fps、63 个两帧蓄力保持、共享资源隔离、行走速度与脚点。扩展动作测试 7,827 项通过。
- 主角完整动作 620 项、运动连续性 1,328 项通过，覆盖全部默认小偶状态、两侧转身全部四帧、立即游戏朝向、动作打断、距离相位与原有移动行为。
- 原生短足跑步 10,442 项通过，最大测得支撑脚滑移 0.000252 世界像素；敌人原画完整性 3,325 项通过。
- 原生战斗、技能美术、视觉预算、镜头跟随与房间镜头稳定性通过。完整 CI 由 PR 的检查结果记录。
- [第一章原生实机录像](../artifacts/thread_doll_v1/gameplay-review.mp4) 包含跑动、跳跃、下落、双向转身、攻击和敌人，480 帧；[32 状态预览](../artifacts/thread_doll_v1/actions-review.mp4) 单独展示完整动作。录像用于主观复核，不作为真实帧时间性能证明。
