# PR #54：入口切换导致的邻区压力超时修复

日期：2026-10-14。修复基线为 `cf492da4d739fb3f105290d500a7d409a85e3036`，继续推送同一个PR。

## 失败与根因

原提交的[运行时CI](https://github.com/superman2003/Crimson-Thread-Pilgrimage/actions/runs/38581909924/job/115913705993)运行80套，79套通过，`world_neighbor_gameplay_stress`在180秒超时。Windows/Linux桌面CI均通过；随后的地图、邻区画面对照和UI像素步骤因前序失败跳过，不能计作通过。

压力脚本执行80轮双邻区缓存切换，每轮交替改变入口X坐标，每5轮离开预取范围。旧 `_invalidate_configs`把入口坐标也作为已发布地区配置的失效条件；换入口会丢掉完全相同的raw/prepared，重新后台读取JSON并完整逐项验证，然后才重建碰撞与角色。按旧循环逻辑会重复启动160次配置读取；该数量来自代码路径分析，原超时日志没有输出已完成轮数，不把它当作实测数据。

## 最终修复

已完整校验的地区配置按地区、路径和文件时间戳保留。仅入口变化且新落点仍位于已校验世界边界内时，执行一次常数规模落点检查并更新入口记录，复用raw/prepared。碰撞与角色仍使用各自入口租约，在入口变化时退休旧对象并重新预建；不会沿用不匹配的演员。

落点检查与完整验证器共用 `entry_in_bounds`，保留原有包含边界的容差，拒绝越界与非有限坐标。失败记录没有已校验世界，入口变化仍需重试；文件/路径/代数变化、离开范围与尚未发布的入口变化继续废弃原任务或缓存。后台线程数量、8步/2ms准入、所有权上限、取消与前台切区优先规则保留。

新增配置专项验证已发布配置换入口不增加读取/完整验证步数、边界容差、越界不得复用和失败后恢复。80轮压力新增读取/验证复用断言，每10轮输出读取数、验证步数、入口重检和耗时。原80轮、默认180秒、两项预建/退休准入、角色一次性退休、来源场景/群组/进度与音频清理断言继续执行；运行器和绘制模式没有修改。
