# 存档损坏、版本迁移与构筑按剧情重建（T02）

修订方案 T02 要求旧饰品容量／固定槽迁到分类槽，地图、绘针、定位、笔记、材料、世界阶段独立保存，损坏提示与备份恢复可靠。台账待验收项是“损坏、版本迁移与构筑剧情恢复”。

存档底层已经比较完整：原子写入、每次写入前保留 `.bak`、`restore_backup` 恢复前把损坏原件另存、世界存档 v1→v3 与构筑 v1→v3 迁移，以及模型层的 `save_product` 测试。本批用正式 World 加载各种“现在读不了”的存档，看玩家实际会遇到什么。

## 发现的问题

在正式 World 里逐一实测：

| 情况 | 改动前 | 影响 |
|---|---|---|
| 主存档损坏，备份完好 | 以空白进度开局，提示“归途记录无法读取”；之后每次保存都失败 | 不知道其实有一份好的备份，也不知道去哪里恢复 |
| 构筑里有本版本不认识的条目（如改名或删除的铭饰） | 整份构筑作废，用初始构筑；**自动保存在整段旅途中暂停** | 恢复备份没用（备份里是同样的条目），只能开新旅途 |
| 存档所在区域已不在路线中（区域改名或删除） | 启动报错，只有“重试加载”，重试读的还是同一个存档 | **游戏永远进不去** |
| 归途结留在已不存在的区域 | 碎钱永远拿不回 | 少量损失 |
| 第二次“开始新旅途” | 上一次保存的 `.previous` 被直接覆盖 | 更早放弃的旅途丢失 |
| 设置里的“恢复当前槽备份” | 按槽号计算路径，不是当前实际在用的存档文件 | 正式游戏里两者一致，玩家碰不到；但测试和自定义路径下会恢复错文件 |

## 改动

### 损坏存档说明备份情况

开局读取失败时检查 `.bak`：

- 备份可用：“归途记录损坏，原文件已保留，本次进度不会写入。找到可用备份（N 区 · M 碎钱）：在设置里选‘恢复当前槽备份’即可接着走。”
- 备份也坏：说明备份无法读取，原文件保留。

损坏的原文件仍然永不覆盖；恢复备份前原件仍另存。

### 构筑按剧情进度重建

本版本写过（或能迁移）的构筑（版本 1–3）读取失败时：

1. 先把原存档原样另存为 `<存档>.before_build_repair_<时间>`。
2. 解锁从剧情标记和遗物重新推出：契印、技能、战具、铭饰本来就由人物和遗物授予。
3. 存档里本版本仍认识的内容逐项走正常的校验路径带回：已解锁条目、契印、各槽装备、活动槽、校习方向、战具次数（不超过上限）、构筑方案。
4. 认不出或带不回的条目列在提示里（最多四项）。
5. 自动保存照常继续；下次启动正常读取，不会再重建一次。

更新版本游戏写的构筑（版本号高于 3）不重建：自动保存照旧暂停，文件原样保留。这是原有约定，旧版游戏不能覆盖新版进度，`world_resume_regression` 有专门检查。

### 区域不在路线中：从起点继续

存档所在区域不在当前路线时，不再停在启动错误页。所有进度（构筑、其他区域、剧情、背包）保留，从巡礼起点继续，并提示原因。下一次保存就指向有效区域。

留在已不存在区域的归途结，碎钱直接退回钱包。

### 连续开始新旅途

`.previous` 仍是最近一次放弃的旅途，现有测试和流程都依赖这个名字。再次开始新旅途前，旧的 `.previous` 先另存为 `.previous.earlier_<时间>`，不再被覆盖。另存失败时新旅途不开始，与原有的失败处理一致。

### 恢复当前槽备份

当前槽恢复的是这段旅途实际在用的存档文件，恢复后的重新加载也读这个文件。

## 验证

- 新增 `save_recovery` 套件（正式 World，34 项、0 失败，加入默认 CI）：
  - 主存档损坏、备份完好：提示里有“找到可用备份”和碎钱数；损坏文件不被覆盖；设置的恢复按钮生效；恢复后碎钱、契印、铭饰和其他区域进度都回来，没有残留警告；损坏原件逐字节保留；之后自动保存正常。
  - 主存档和备份都坏：提示说明备份也无法读取，原文件不动。
  - 构筑含未知铭饰（已装备、也在一个构筑方案里）和未知机制：不暂停保存；提示说明已重建并列出 `wayfinder`；司铸契印与机制、已装备的铭饰、守钟校习方向保留；合法的方案保留、引用未知铭饰的方案丢弃；原存档逐字节另存；能保存；下次启动正常读取、不再二次重建。
  - 更新版本的构筑（版本 4）：自动保存暂停，文件不动，不另存。
  - 区域已删除：从苔钟庭起点继续并说明原因；构筑和其他区域进度保留；该区域归途结的碎钱退回；保存后存档指向有效区域。
  - v1 世界存档（无构筑）：碎钱保留、剧情标记授予契印、能保存。v2 世界存档 + v2 构筑：迁移到 v3、铭饰保留、无重建提示、能保存。

- 把三处源码改动退回 main 原样，`save_recovery` 有 16 项失败，且没有输出完成标记。

## 与 #145 的关系

`save_recovery` 的夹具用“司铸＋绊线钉”。如果用“司铸＋只带初始投罐”，会撞上 #145 里修的另一个读档错误（没有可用战具时活动槽读不回）。两个 PR 合并后，重建同样会保留 #145 新增的 `crafted` 字段（由 `restore()` 校验）。
