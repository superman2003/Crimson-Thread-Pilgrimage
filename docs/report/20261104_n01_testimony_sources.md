# N01／N04：六份证词的实物出处与推断边界

日期：2026-11-04。对应台账 N01 主线因果与 N04 场景叙事子项。

## 玩家看到的变化

此前证词详情会陈述结论、场景印证与互证，但没有分开“实物上看到了什么”和“据此仍然不能知道什么”。现在取得证词后，在原有旅记条目内直接补充四层说明：

1. 证词出处：拾取时所在房间与实物载体。
2. 可确认的实物痕迹：可在场景叙述中核对的细节。
3. 这些痕迹能支持：该证物足以支持的有限判断。
4. 仍不能据此断言：没有署名、缺失记录或居民意愿，保留未知。

| 证词 | 实物出处 | 保留的未知 |
|---|---|---|
| 苔钟庭 | 井喉的先后刻痕 | 谁下令追加抵押 |
| 铸雨渠 | 沉没档案舱的双面工牌 | 未能辨认的全部姓名 |
| 盐白书库 | 封存书堆的改字原页 | 改字者与准确年月 |
| 断弦温室 | 大树之心的旧弦、新箍 | 徽是否同意后来接弦 |
| 黑曜巡礼道 | 巡礼军墓的重编名册 | 被重新编入者的回答 |
| 无声王冠 | 冠肋内侧的锁钥痕 | 门外来者的姓名 |

八条“与已取得证词对读”分别讲明独立证物怎样相互支持，以及相似机制为什么不等于相同责任人。条件按当前真实持有量计算，已知标记、旧页面引用或零数量都不能解锁另一份证词的来源。

## 实现与存档

- `testimony_sources.json` 只保存作者写好的来源说明，不增加物品、任务或结局条件。
- `testimony_sources.gd` 是纯读取；公开结果删除未解锁对读的条件与正文。
- 正式 `_journal_presentation` 追加同一份文本，因此旅记搜索与阅读内容一致。
- 旧存档按已有物品恢复显示，不新增存档字段；外部调用无法修改缓存中的作者资料。

## 验证

- 数据门核对六份来源与原证词、真实房间和收集物一致；五组植入错误必须被拒绝。
- Godot 覆盖全部 64 种证词持有组合，逐条检查八条对读门控；负数、小数、布尔、字符串、无穷及未知物品不能充当证据。
- 正式 World 旅记验证出处展示、跨证词条件变化、搜索文本一致及阅读不修改剧情状态。
- 新验证接入已有 `narrative_closure`，与全部 720 种取证顺序、结局预览／取消、失败回滚及重启恢复一起执行。
- campaign、叙事数据、runner 与分片检查均执行；最终运行数量见 PR 验证记录。
