# E03/G01：完整心结与能量纺锤的实际容量

基线 main `5f1fa82663fca3df131f3d9d5e6a65483b1a232c`。原完整心结、能量纺锤的目录与物件说明承诺增加生命／能量上限，但生产收集与 NPC 奖励只增加背包数量；构筑每次仍返回固定 5HP／100 线。本批兑现两个原奖励，不改变任何来源、掉落量、价格、能力门或契印疗伤规则。46 项最终验收保持 OPEN。

## 行为

目录显式规定每个完整心结增加 1 格生命上限，每只完整纺锤增加 20 点绯线上限。碎片不冒充完整物件。本次确定具体增量，原说明没有写数量。物件说明同步写清增量与“拾取不回复”，防止玩家把容量当补给。

BuildSystem 从现有世界库存推导容量，不增加存档字段，不把数量写入装备方案，也不在同步时累加历史结果。三契印、方案预览／恢复均读取相同进度；新旅途 reset 清除旧进度。原有存档已经持有的完整物件从本版开始生效。计数必须是有限、非负的整数值；JSON 的整数浮点表示可读，小数或负数不给容量。

生产 `_add_inventory_item` 对两种完整升级同步构筑，实际物理拾取与 NPC 奖励共用此入口。Player 在只有容量改变时保留正在进行的攻击、格挡和已付款疗伤预约，只更新上限并夹紧现有资源；不会走完整换装的动作清理，也不免费补满。真正换契印仍执行原清理规则。正常钟龛休整才填充到新上限。

## 失败与范围

初次组件缺字体缓存，断言虽通过但 ERROR 使运行器拒绝；初次 World 缺 map 纹理缓存导致编译失败／180秒超时，依赖保存不存在的下一阶段被明确停止。按相同原图 SHA／导入参数恢复可再生缓存后继续，没有改生产素材。初次重启字典比较因 JSON int／float 类型不同失败，改为递归比较全部键、类型与数值，未截断小数；随后三个进程通过。补完成标记时首次 CRLF 匹配失败，修正仅对匹配文本规范换行，原始日志保留不变。空的 component01 准备日志没有可用的引擎退出证据，不计通过。
