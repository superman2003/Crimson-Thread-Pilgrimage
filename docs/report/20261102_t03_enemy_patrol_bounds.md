# T03：敌人巡逻范围不再逐步全图扫描

接续 T03 与 #498 的测量：传送／读档的构建阶段里，单个 `_enemy` 任务 30–80ms。起点为 main。所有 46 个任务包的最终验收仍开放。

## 原因

逐段计时后，敌人生成里的时间几乎都花在 `_enemy_platform_movement_bounds`：从出生点向左右每 8–18px 走一步，每一步调用一次 `_enemy_spawn_rect_clear`，而后者每次都扫描本区全部平台（苔钟庭约 145 个）、全部岩体矩形（282 块）和地形多边形。一块长平台要走上百步，单个敌人 10–126ms。出生点修正、脚下平台查找和飞行高度调整合计只有 1–5ms。

## 现在

每个敌人只在开始行走前筛一次：取这块平台整段行走范围（左右各多一步、加上身宽和身高）的扫掠矩形，留下与它相交、且满足原过滤条件的岩体和平台（不含脚下平台、不含已被地形多边形替代的锚点矩形、不在脚面以下），地形只在扫掠矩形与地形相交时才逐步检测。之后每一步只测这些障碍。任何会与某一步身体矩形相交的障碍必然与扫掠矩形相交，所以每一步的判定和原来完全相同，走出的左右边界也完全相同。

## 验证

- `pilgrimage_merge_regression` 内的出生点等价测试（`enemy_spawn_search_validation.gd`）新增巡逻范围比对：原函数逐字冻结在测试的 `Legacy` 类中，六区全部敌人与首领、两组固定夹具和 24 组随机布局上，新旧巡逻范围完全相同（333 处非空范围），且新的行走不再调用完整的 `_enemy_spawn_rect_clear`。共 1406 项通过。反向：把扫掠矩形缩小 20px，32 处巡逻范围不一致。
- `world_async_loading`、`enemy_lifecycle_regression`、`world_enemy_residency`、`world_neighbor_gameplay` 通过。

## 边界

只改了巡逻范围计算；出生点搜索和敌人运行中的 `_enemy_spawn_rect_clear` 调用不变。构建阶段剩下的单个任务主要是首次见到某张物品图集时的解码（收集物，每张约 80–100ms，一次性）和练习靶生成。
