# T04：书库烛台落点与开启伤害的三地区回环

## 改动

从下方台阶跳上 `candle_floor` 时，原孢蜡烛台的伤害矩形右沿为 1690，而平台右沿为 1670，超出 20px。开启伤害的回放在首次落台前受击，跌回下层，无法按原输入继续取得二段跳。把同一个 110×22、伤害 1 的矩形从 x=1580 移至 x=1480，使左右各留 80px 可站立边缘；二段跳拾取从 x=1510 移至 x=1440，放在左侧安全边缘。玩家从右侧落台，跳过烛台取能力，再跳回原返程入口。平台、敌人、伤害与能力条件均沿用原数据。

已有 `world_route_walk` 导航回归同步走右侧落点与左侧拾取点，仍明确标记 `damage_suppression=true`，不作为战斗证据。另加入可独立重放的 `world_damage_route_playback.gd` 与 `tools/run_damage_route.py`，固定 60Hz 输入步进，运行真实 Player 碰撞、敌人 AI、攻击、疗伤和 F 交互；不写入玩家位置、生命、能量、库存或钱包，不启用调试无敌。

## 已取得的证据

在 main `97da0545` 加本批源码的 Windows / Godot 4.6.1 原生 NVIDIA GL 下，最终三地区回环通过：新档 0 碎钱，先看到盐风门阻挡，再走排水管取得攀墙，走立管至书库取得二段跳，回访盐风门领取失名证词，双向使用永久捷径，释放宿主并从同一存档重新创建 World，能力、证词、捷径和记忆钟龛均恢复。

最终回放 26 步、6459 物理帧，记录 3 次真实扣血、2 次消耗能量的疗伤、0 死亡；沿途敌人掉落使钱包达到 32。执行耗时 58.61 秒，8679 份项目文件前后 SHA256 一致，退出 0 ERROR / 0 ObjectDB 泄漏警告。固定步进会加速模拟，耗时与帧数不能用于宣称帧率或真人通关时长。原始日志与来源见 `artifacts/t04_candle_route/final_native/`。

反例采用完全相同的最终回放脚本，只把上述两份数据还原为 main 版本，必须在书库烛台路线失败；失败原始输出和恢复后的数据校验见 `old_geometry_expected_failure/` 与 `negative_restoration.json`。这不是用另一套较弱输入替代旧版。

相关原生 GL 回归通过：`salt_archive_experience` 154 项、`world_integration` 67 项、`world_route_access` 553 项、`world_route_walk` 26 步；最后三套夹具各有 1 条 ObjectDB 退出警告，均保留在日志中，不计入“最终独立回放零警告”的结论。四套运行前后 8679 份项目文件一致。`npm test`、campaign 与新 runner 的 Python 编译检查通过。旧数据反例耗时 52.97 秒，在 (1640,2240) 落点失败、实际跌至约 (1635,2612)，退出 1 / 1 条 ObjectDB 警告，随后逐字节恢复最终两份数据。

## 重放

先按 `docs/VALIDATION.md` 导入资源，再运行：

```sh
python tools/run_damage_route.py --engine /path/to/godot --native-gl --log-dir /tmp/damage-route
```

Linux 可省略 `--native-gl` 使用仓库已有的软件 GL。该独立播放保留严格 180 秒超时，拒绝非零退出、ERROR、缺失完成标记及源码变化，记录退出警告；不进入默认组件套件清单。默认导航套件继续提供不同范围的验证。日志会保存前后文件哈希、工作区补丁、脚本与 runner 副本。
