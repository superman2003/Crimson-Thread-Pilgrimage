# T03 分帧音频准备、取消与退出退休

本轮续修 PR #541，基于 main `0fc65b199ef64c3c040c8035931f018f1e228b9b`（已含 #550、#547、#549）。保留原三项音频准备、同步兼容入口、设置分帧、来源备份及六区空间环境声。原 v13 的单项 CPU 对照属于历史测量；本轮没有重新测量性能。

## 实现

- `AudioDirector.release_region_audio()` 先记录乐句，再关闭自动播放、停止处理和环境定时器、终止本地音量动画、以弱引用观察所有播放实例并摘掉流；覆盖挂在 Main 上的探索播放器。重复调用与随后退树安全，迟到的音乐／环境床调用不能重新启动旧导演。
- Main 在分帧逐项移除节点前调用统一退场；排队删除的宿主不再启动后续音乐项。同步 `_build_audio()` 仍依次执行相同三项，新准备创建新导演并沿用原乐句书签。
- 首启已有的自有帧唤醒扩展至前台切区，包括预检、卸载及构建。宿主 `shutdown()` 能立即展开等待栈，令牌完成后解除帧转发。无令牌的直接调用仍等待 SceneTree 原帧，预算及取消检查保留。
- 真实 World 退场之后的续播回归保留原时间位置断言，并检查旧导演不能重启、新准备接手播放。六区空间声的章节清理迁入 `prepare_chapter()`，没有丢弃主线的新行为。

## 已验证

- Godot 4.6.1 严格资源导入两轮通过。
- 新专项 233 项：六章逐项实际解码、同步一致性、12 次显式退场与迟到调用、三阶段实际 World 取消，以及三阶段排队删除真实 World。目的地 0／1／2 条流、令牌／导演／播放弱引用、来源存档与库存进度均实际检查。
- 独立临时项目反向检查使用相同最终专项与同一批真实资源，不修改正在验证的生产文件：恢复“只有首启使用自有帧”准确失败 3 项，恢复 Main 仅记录乐句的旧退场准确失败 38 项；均无 SCRIPT ERROR。
- 音频专项在集成 runner 中拒绝 ObjectDB、资源仍使用、泄漏实例和悬挂完成状态；36 项工具检查包含“成功标记＋退出泄漏必须失败”。18 项长跑工具、分片、工作流、npm 和章节审计通过。
- 软件 OpenGL 九套全部通过：新专项、音频退休／乐句、声音地标、空间环境声／实际 World、物品预热 244、准备预算 174、来源备份 123、六区异步切换。最终无头退休、World 宿主 539 与首启预算三套通过；另有同源无头新专项 233 项通过。没有 ObjectDB／资源残留或脚本错误。
- 短时组合的引擎完成 3 轮、21 次切区、3 次死亡、63 次 UI 开关，输出 `RUNTIME_SOAK_PASS`，54.95 秒为热身后的测量时长；源字节前后不变、引擎退出零错误及资源警告。但外部工具严格拒绝：当前容器的 `/proc` 属于外层 PID 命名空间，读不到引擎报告的 PID 13 的驻留内存，39 次采样均无有效驻留值。本轮不计“组合全部通过”或长跑完成，原失败完整归档，CI 使用正常进程环境继续验收。
- 原始导入、九套 GL、最终无头及完整短探针含输入 SHA／进程回执存于 `raw-runtime-evidence.tar.gz`。短探针的 `revision` 是提交前旧分支头；实际工作树已同步本报告基线并包含本轮修复，`tested-source.json` 固定改动源码 SHA256，全量冻结清单在归档内。

## 原始失败与范围

`attempts/` 保留了本轮首次运行缺少导入和 WeakRef 类型推断失败、227 项断言完成后仍泄漏三份前台令牌／协程的实际退出日志及 verbose 身份，以及续播夹具切换到新导演时的两个中间失败。没有删除断言或放宽退出门禁。

旧 #548 的 CI [owned-workers 失败](https://github.com/superman2003/Crimson-Thread-Pilgrimage/actions/runs/42199737437) 报告的是 Ogg 播放残留；本地新捕获的前台令牌泄漏有自己的明确身份与可重复反向，不把两者认定为同一根因。最新 main 已含物品夹具的显式音频观察与退休，本轮组合继续覆盖它。

软件 GL 是实际 OpenGL 后端与 Dummy 音频；保留虚拟显示器不能设置 VSync 的能力提示。它不代表独立显卡、Windows 发行包、耳机实听、自然通关或帧率验收。生命周期短探针不能替代 30 分钟长跑。T03／T04／T05 最终项继续 OPEN；远端检查以新 PR 头为准。
