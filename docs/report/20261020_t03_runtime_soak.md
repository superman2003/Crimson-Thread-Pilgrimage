# T03：真实生命周期压力工具与角色音频清理

本批承接 #167 的正式 World 音乐释放顺序修复，增加可重复的六区长时验证。PR 短探针仍运行两轮六区热身和一轮测量；完整验收测量三十分钟。协议、指标、提前固定的漂移上限及证据边界见 `docs/RUNTIME_SOAK.md`，不替代 T04 自然通关。

压力测试发现，每轮七次切区和一次死亡会在保留的 Player 下多留八个短音效节点。区域清理调用 stop 后不会发出 finished，原来仅依赖 finished 删除的落地/脚步播放器便积累；同一清理会把持续滑墙播放器的流置空，下一次滑墙却不重新加载。本批标记一次性播放器，在递归退休时排队删除，持续播放器保留但缺流时重新取得。退休观测使用实际 has_stream_playback，覆盖场景禁用或暂停时仍由原生后端持有的播放对象。

新增实际 Player 场景的 12 项检查，只覆盖显示后端静音谓词以便无头 CI 也能发起真实音频，其余走原生产播放、退休和重用方法。未修生产时五项失败；最终六套真实 GL 通过：audio_retirement（音乐 16 项、Player 12 项及原音频/音量检查）、world_enemy_residency 56、world_resume_regression 38、world_death_cache_flush 27、seal_presentation 175、player_state_cleanup 9。十项 Python 测试验证缺时长、漂移、孤立节点、缓存越界和缺动作等证据会被拒绝。

同步 #164 已有的真实时钟 CI 修复：audio_retirement 不再采用加速 fixed-fps，并保留其双渲染命令测试；不改变其它套件的原时限。本机 Windows 的 31 项 POSIX 可执行夹具按既有规则跳过，需 Linux CI 验证，不记为本机执行通过。

开发探针全部保留在本地，关键结果汇总为 `artifacts/t03_runtime_soak_development/probes.json`。早期缺 API 的编译失败和开发期间改源触发的冻结失败没有算通过；退出 ObjectDB warning 也会使新 runner 判失败，即便引擎断言与完成标记通过。

组合长跑已在独立工作区的固定生产源 `b04a1b0977167092b66b5e11433a97002713596f` 上结束，含 #154–167 的相关实现及角色短音效/滑墙修复；它没有此后 has_stream_playback 观测补充或 #169 的待挂载音效清理，不能代表当前 PR 头。8667 份源文件冻结前后一致，Godot 4.6.1、原生 GL、音频 Dummy，真实墙钟运行 1918.156 秒；两轮热身后测量 1815.465 秒，完成 40 轮、280 次切区、40 次死亡重生及 840 次界面开关。

所有同位置采样的节点数均为 1234，不再每轮增加八个；最终孤立节点为 0，已观察音频全部释放，剩余声部为 0。热身后静态内存净增长 1,795,525 字节（约 1.71 MiB），增长斜率 61,863.8 字节/分钟（约 0.059 MiB/分钟），在运行前固定的 64 MiB 净增长和 1 MiB/分钟上限内。这些是本次生命周期诊断结果，不能证明目标硬件帧率；全程最大帧间隔约 1.452 秒，实际帧时间分布保留在原始指标中。

**长时验收失败，PR 保持草稿。** 引擎断言与完成标记通过、退出码为 0、没有 ERROR，但退出时仍报告 ObjectDB 泄漏，verbose 日志列出 15 个引用数为 0 的 RefCounted 实例。短探针中观测到的单个实例不是长跑终态的数量。runner 因此正确返回失败，`passed=false`、`long_session=false`；最终孤立节点为 0 不等于所有 RefCounted 都已释放。增加退出帧、延时或追加实例 ID 检查没有证明能消除它，尚未确认根因。
