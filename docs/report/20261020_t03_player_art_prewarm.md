# T03：主角导入图片在启动准备期间预读

冷进程中，首次生成 Player 会在 `_ready` 同步读取身体动画和分层待机的 132 张导入图片。隔离诊断把初次 `_finish_region_spawn` 的 1,345,161 微秒定位到这里。本批在启动加载画面出现后立即启动一个低优先级、私有的后台 Thread，与路线、区域准备及构建重叠；在提交生成 Player 前领取结果，真实 Player 建立自己的动画与纹理引用后立即清空临时引用。

worker 只读不可变 JSON 与导入图片，不创建 Node、SpriteFrames，不操作 SceneTree、Player 状态或脚本的共享可变缓存。它持有一个任务与尚未领取的结果，正常轮询只在完成后 join；普通取消保留这个有界所有者，重试可领取，整宿主退出负责 join 并释放。新增一个主角启动任务，不等于全局线程数量不变；原角色图集队列的两请求上限、构建每帧最多八操作与 2ms 准入窗口保持原值，准入窗口不保证单项耗时。

主角必需的身体图片缺失、清单错误或程序纹理 `.tres/.res` 会返回明确的启动错误，不公布部分结果。分层待机是原 Player 的可选增强：缺清单、形状不合法或缺图片时仅跳过预热，保留身体待机回退。未改 Player、素材、动画节奏或玩法参数。

同一份诊断脚本（SHA-256 `9dccacf94d1c39a4b151e28bbe0c6d509b20cd0eca9bacec43061680cd16758d`）在 Godot 4.6.1 / Windows 原生 GL 中分别运行三个循环、21 次切区；每次都是新进程，期间没有其它本机 Godot 运行，未清空操作系统或导入缓存。基线 `9476eea942a96db471cae9e9e88992b8023cfe42` 与原型 `f0ceffe22f574fefa2dfdca84ede89027e1ef52d` 的差异补丁和日志均归档：

- 初次主角生成提交：1,345,161 → 4,400 微秒。
- 诊断采样区间的最大帧间隔：1,351,895 → 223,184 微秒，剩余尖峰出现在铸雨渠构建 cursor 295 附近。
- 初始 World PackedScene 读取：1,083,062 → 1,110,841 微秒；它仍然存在，并不包含在后者的过程帧间隔采样中。
- 两次诊断都没有断言失败、ERROR、warning；最终孤立节点和声部均为零。这是带显式旅行和战斗夹具的短测，不能代替自然流程、完整长跑或目标机器帧率验收。

性能对照的原型只包含预读模块和加载器接入。最终代码额外将文件时间取样移到读取前，补充标量快照及可选待机回退，不能宣称原型与最终五份源码逐字节一致；当前有效素材均为同样 132 张。最终五份源码哈希在归档时记录，不冒充运行前后的全源冻结。

最终定向回归在真实 Player 场景检查原生资源缓存、所有身体动画及分层待机，实际 `_ready` 没有首次同步图片读取；缺失主图、程序纹理、错误 JSON、可选清单/图片失败、领取一次与立即退出均覆盖。最终 `character_art_prewarm` 的主角部分 213 项、原角色部分 833 项通过且退出零泄漏；`world_startup_budget` 包含启动确在线程预读和临时引用释放两项正式 World 检查，断言通过，退出有一次 ObjectDB 警告，保留待查。

此前六套矩阵全部断言通过：图集预热、启动预算、后台配置 1054 项、分层待机 212 项真实 GL 像素、动作连续性 1192 项、恢复 38 项。其中 `world_resume_regression` 留有一次 ObjectDB 警告，其余五套该轮没有；这些局部回归不能记为全局 T03 零警告。严格两轮恢复模式导入、npm test、campaign、23 项发布构建单测（1 项按原规则跳过）及 5 项 workflow 检查通过；Windows 的 31/11 项 POSIX 夹具按既有规则跳过，未记为实际执行通过。

最终源码默认主场景另以当前发布脚本的原参数 `--headless --verbose --max-fps 60 --quit-after 1200` 执行新档与恢复，使用独立临时用户数据。两次均成功发布区域，写存档；恢复保留探针并生成备份/写回，均无 ERROR 或 warning。132 张图片均由后台预读，额外等待帧数 0，可选跳过数 0，Player 接管后临时所有者为零。实际运行分别约 24.69／25.44 秒。这是源项目启动验收；本机没有导出模板，Windows/Linux 实际发布包仍以新提交的远端构建为准。辅助驱动首次相对路径调用在加载项目前退出，原日志保留，最终使用绝对项目路径。

所有压缩原日志、脚本、原型补丁、最终源码哈希与检查摘要在 [artifacts/t03_player_art_prewarm](../../artifacts/t03_player_art_prewarm/verification.json)。新的模块路径接入已有后台资源所有权 CI，原默认套件数量不变。本批基于 #168 的组合，包含 #170 的后台资源回收，单独建立以该分支为基底的依赖 PR。
