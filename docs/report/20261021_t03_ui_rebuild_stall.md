# T03：区域切换时界面重建不再单帧卡顿 100–260ms

台账 T03 记有“约 154ms 的区域构建批次”尖峰。在真实 GL 下依次切换六个区域两轮，读取区域加载器自带的逐步耗时（`commit_operation_usec`），最慢的都是界面外壳重建：每次切区都新建 `ui_shell`，设置页 130–260ms、行囊 115–150ms、构筑页 105–180ms、地图初始化 40–90ms，每项都是不可再拆的单个提交步骤，加载画面期间整帧停住。

定位过程：

- 微基准显示，同一个 Button 在加入场景树之前设置文字要 3–4ms，加入之后再设只要 0.1ms；Label 在树外同时设置文字和尺寸也要约 4ms。与字体无关：完整字库与 NotoSansSC 相同，把引擎后备字体设成项目字库也不变。原因是控件在树外排版文字代价很高，而 `_label`、`_button` 两个通用辅助函数都是先设文字和样式、最后才 `add_child`，几乎所有面板都经由它们创建。
- 设置、行囊和构筑页标题使用 1–2MB 的铭刻标题图，每次 `load()`。旧界面释放时贴图随之释放，每次切区都重新解码，单张约 30ms。
- 设置页的 4 个开关、地图商人与召回对话框、图钉类型菜单与状态行也是先设文字再入树。

修复：`_label`/`_button` 在树外只设置位置、尺寸与样式覆盖，入树后再设文字；铭刻标题图改为 `inscription_mark()` 静态共享缓存；开关、两个对话框、图钉菜单与状态行改为先入树再填文字与选项。控件、文字、字号、样式与交互不变。

结果（同一探针，六区两轮）：提交阶段最慢批次由 130–260ms 降到 19–37ms（一次 49ms）；设置页由 130–260ms 降到 10–25ms，构筑页约 7–16ms，行囊约 6–15ms。地形与平台构建阶段仍有 80–200ms 的批次（`max_batch_usec`），与界面无关，留待后续单列。数字是本机原生 GL 单次测量，不作为目标硬件帧率承诺。

新增默认套件 `ui_text_order`（9 项，不依赖计时）：在父节点 `child_entered_tree` 时记录控件当时的文字，要求 `_label`、`_button`、地图商人与召回对话框、图钉菜单与状态行入树时仍为空，样式照常生效，标题图共享同一份。换回原代码时失败。`ui_redesign`、`ui_world_integration`、`ui_build_accessibility`、`settings_remap`、`input_prompt`、`inventory_map`、`map_player_pins`、`global_font`、`world_startup_budget`、`save_product` 通过；`survey_map_knowledge` 在 headless 下需约 240 秒（超过本地默认 180 秒时限，CI 中由其工作流以 GL 运行），放宽时限后 190 项通过。
