# T05：按真实运行时引用审计发布包内容

导出预设原先只按 `*_validation.gd`、`capture_*` 等写法排除测试脚本。近期新增的路线回放（`world_*_route_playback.gd`）、夹具、探针、验证辅助、地图图钉布局检查，以及 #178 的字体样张场景都不在排除列表里，会随玩家发布包一起打出。

新增 `tools/audit_export_contents.py`：从主场景和自动加载出发，跟随脚本、场景、资源和 JSON 数据里的每个 `res://` 字面路径与 `class_name` 引用，得到运行时实际可达的文件，再逐个导出预设检查三条：可达的脚本/场景不得被排除（否则发布包会坏）；不可达的脚本/场景必须被排除；可达的 `res://` 引用必须存在。运行时拼接出的脚本或场景路径无法静态跟踪，出现即报错并要求人工审查；按区域 id 拼接的音频、图片与数据路径由包含规则整体导出，不在此列。

当前 main：264 个脚本中运行时可达 81 个（含场景与资源）；14 个开发用文件（6 个回放/夹具/探针脚本、3 个验证辅助、地图图钉检查、`enemy_dummy.gd`、字体样张脚本与场景、无任何引用的旧 `GeneratedMain.tscn`）原会被两个桌面预设打包。两份预设的 `exclude_filter` 现增加 `scripts/*_playback.gd`、`*_probe.gd`、`*_fixture.gd`、`*_helper.gd`、`*_checks.gd` 及上述个别文件，审计通过（81 个运行时文件全部保留、无误排除、无缺失引用、无动态脚本路径）。

`tools/test_export_audit.py` 用临时工程验证：干净工程通过（含 `class_name` 与 `.gdshader` 引用）、打包回放脚本、排除运行时脚本、缺失引用与动态脚本路径各自被拒绝。`npm test` 新增 `test:export`，发布候选工作流在构建前运行审计；该工作流随本 PR 在 Windows/Linux 实际导出并启动发布包，验证排除没有误删运行时文件。

不在本批：许可、入口与结局文本一致性及最终候选包人工验收。
