# T05：经 SHA512 校验的发布引擎下载重试

PR #542 的原头 a13c4760 中，Windows 与 Linux 发布任务都在安装引擎／模板阶段因 HTTP 504 失败，尚未执行导出。原工作流直接调用 urlretrieve，没有下载重试。本批仅调整桌面发布安装工具；游戏代码、Godot 4.6.1 版本、编辑器／模板配对、实际发布包启动与读写门禁保持。

## 安装规则

- 官方同版本 HTTPS 地址与 SHA512 清单继续使用。每个请求最多 5 次，阻塞网络操作超时 45 秒，失败后分别等待 5／10／20／40 秒；这不是整个下载的 45 秒墙钟上限。仅对暂时 HTTP 错误、连接／超时、截断响应及校验失败重试；永久 HTTP 错误和证书校验失败直接拒绝。
- 每次写独占暂存文件，完整长度与 SHA512 通过后才替换归档。缓存也必须匹配本次官方摘要；清单重新获取，不以旧清单或其它镜像兜底。失败保留原目的文件并清理本次暂存文件。
- 仅提取所选编辑器及匹配模板的精确成员，ZIP CRC 同样生效。两个归档和成员都成功后才向 GITHUB_ENV 发布 GODOT；旧安装回执在开始时清除，新回执记录归档及实际安装二进制的 SHA512。未更改后续 build_release 的版本检查、导出、首启、续档和写回校验。
- 新工具和测试同时进入 pull_request／push 的发布路径过滤器，两个原平台矩阵保留。安装回执随发布日志收存。其它回归工作流的下载路径仍保持原状，本批不声称已解决全部外部网络错误。

## 验证

14 项测试使用真实本地 HTTP 服务，覆盖 504→503→成功、永久 404、重试耗尽、截断、错误摘要、已验证缓存、清单刷新、无效／重复清单、两种平台精确成员、配对错误、缺少模板／摘要、不发布旧回执及 ZIP CRC 损坏。既有发布构建测试 23 项通过判定，其中本机 Windows 的符号链接夹具跳过 1 项，不能记为已执行。

临时取消下载后的 SHA512 检查，错误摘要测试准确失败；还原生产 SHA 后再次通过 14 项。YAML 实际解析，并核对两个平台配对、两种事件路径、真实安装入口和回执收存。证据位于 artifacts/t05_verified_downloads_v16/。本地 HTTP 与伪二进制 ZIP 只证明下载／安装协议，不替代官方编辑器、模板和实际发布包；两平台 CI 的新头结果另行追加。

## TLS 读取中途断连与新头复验

审阅指出 HTTPS 响应已打开后，read 可能直接抛出 SSLEOFError，它不属于 ConnectionError／URLError；本批明确将该提前 EOF 纳入相同重试次数与退避，未扩大为所有 SSLError。新增读取中途 EOF 后恢复、EOF 持续发生时次数上限，以及直接／包装的证书验证失败始终不重试，完整工具检查由 14 增至 17 项。暂时移除此类型处理时，两项 EOF 测试报错，恢复源码 SHA 后 17 项重新通过。

修正前头 fedccd2d 的两平台实际发布 CI 已通过，合并候选 d7387e173c66 完成官方编辑器／模板校验安装、实际 ZIP、首启／续档／写回。TLS 修正新头的 CI 另行复验，不把旧头结果算到新头。原始日志与恢复证明见 artifacts/t05_verified_downloads_v16/。
