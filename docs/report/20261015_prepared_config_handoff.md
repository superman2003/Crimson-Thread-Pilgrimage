# World prepared configuration handoff

This increment continues W00b2b from PR #62 (`193427e`). The remaining whole-tree copy in `_prepare_config_and_route` is moved out of the persistent World's asynchronous construction path. The loader uses the existing variant-copy job to build a detached configuration in bounded steps before handing it to a dedicated owned-configuration hook. The explicit synchronous preparation method retains its defensive deep copy and route-overlay behavior.

The accepted prepared input is private and read-only while copying. No partially copied tree becomes `host.config`. Successful handoff gives the host an independent nested tree; it does not alias a validator result, a prefetch cache, the route cache, or the rollback snapshot. This does not promise safety for arbitrary external mutation of the private input during the coroutine.

Startup retains its existing path, entry, file and generation lease. Foreground travel must retain the source state accepted during preflight through the handoff window. Rollback restores the settled in-memory departure snapshot rather than requiring the old source file to remain unchanged on disk. Host lifetime, tree attachment, loader/route generation and cancellation are checked across each copy yield and before assignment. Publication and save progression remain at the existing final commit boundary.

The copy edge cap is an admission bound, not a hard duration limit. Copy begin/step work and elapsed wall intervals are measured separately, and target/rollback attempts retain independent records. Key enumeration, an indivisible copy operation, source file probes and other synchronous preparation operations can still exceed a nominal frame budget. Departure configuration/state snapshots, coordinate first read and the direct synchronous compatibility path remain outside this increment.

The legacy preparation work total includes completed copy begin/step work, excluding its yielded time and source/context-probe overhead. A rejected copy retains its measured work in the attempt's copy record; it does not become a completed preparation operation in that aggregate. The synchronous admission-batch maximum does not measure the whole copy coroutine. Copy wall time is sampled after yielded frames, before the following context/source probes.

Prefetch records now retain their original worker-read byte count. Borrowing requires both the original timestamp and byte count to match the file; legacy records without a read size fall back to a fresh worker read. A current file probe cannot give an old cached body a new source lease. Preflight pins this source state before borrowing/reading and checks it after validation; the prepared-copy helper rechecks the same state through acceptance. Equal-time, equal-length replacements remain undetected by this freshness policy. Existing synthetic warm-cache fixtures record the size of their original input bytes; their deliberate test-only content changes are preserved.

Implementation and independent read-only review are complete. Final focused results are recorded below; full remote integration CI remains a separate gate.

The first strict new-suite attempt failed script compilation because two asynchronous-job flags used inferred types with dynamically typed host properties. They now use explicit Boolean declarations. Resource-only recovery imports had passed; those imports do not prove runtime scripts compile. The failed attempt is retained separately and cannot count toward accepted verification.

The first independent nine-suite run also rejected the neighbor-collision fixture: its new source-size field referenced a byte buffer declared in a different function. The buffer is now read, parsed and measured together in the seed function. This is a fixture-only correction; the runtime remains frozen. The original nine-suite aggregate is a failure, and a separate collision replay passed before final acceptance.
