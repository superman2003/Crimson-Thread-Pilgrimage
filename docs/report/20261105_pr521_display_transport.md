# PR #521：修复软件 GL 显示服务的共享内存错误

2026-11-05。修复基于 `cdcac9407d258c214a1951241ba1ac048c2b3518`，保留此前的输入同步与资源下载恢复改动。

## 失败证据

GitHub Actions 运行 `41827346146` 的 `runtime (1)` 共运行 65 套，只有 `hidden_routes` 失败。该套输出 `HIDDEN_ROUTES checks=266 failures=0`，但引擎同时报告大量 `BadShmSeg (invalid shared segment parameter)`，严格 runner 因 477 条引擎错误而返回失败。

## 修改

软件 GL 辅助显示经 TCP 连接；客户端不能依赖与 Xvfb 共用本地 IPC 共享段。启动 Xvfb 时显式关闭 `MIT-SHM` 扩展，避免客户端协商这条不适用的传输路径。继续使用真实 X11、1280×720 画布和软件 OpenGL。

新增六项显示回归，包含真实 X11 扩展查询。原配置下，命令检查与真实扩展协商两项失败；修改后六项通过。检查同时保留显示异常退出、启动失败、清理和超时回收行为。

严格 runner 新增本次日志形态的反例：即使带有隐藏路线的成功标记，`BadShmSeg` 仍必须使测试失败。没有忽略引擎错误、改用无画面模式、跳过场景或缩减 CI 分片。

## 验证

- 显示测试 6 项、严格 runner 35 项、工作流 6 项、分片 3 项通过。
- 同一个实际 Xvfb 上连续启动三个 Godot 4.6.1 OpenGL 客户端；每次绘制三帧并读回颜色像素，均通过且没有引擎错误。
- CI 在安装显示依赖之后执行新的真实 X11 检查，再继续原有完整运行分片。

完整场景资源尚未在本地下载完毕，本次不宣称已本地复跑 65 套场景；隐藏路线及原完整分片由新提交的现有 CI 重跑。
