# 大房间分段记录（U04）

## 背景

修订方案第 3 条：“多数房间进入即会补绘整房，有些房间按实际探索局部揭示。我们的‘大房间分段记录’……属于适配后的产品要求。”此前旅途笔记只按整间房记录：走进钟梯井的入口，补绘后整条 2534 像素高的竖井连同所有地形都会出现在地图上，即使下面从没去过。

## 规则

- **哪些房间分段**：房间宽超过 1.5 个屏幕（1920），或高超过 1.5 个屏幕（1080），就按屏幕大小（1280×720）均分成若干段。六区约二十间受影响，例如钟梯井 1×4 段、苔钟庭中庭 2×3 段、南根道 3×1 段、旗桥 3×2 段。其余房间仍整间记录。
- **记录**：每帧按玩家所在位置记录当前段落，笔记键为 `<房间>@<段号>`；整间已补绘的房间不再记录段落。
- **补绘**：沿用盐墨绘针流程，安坐钟龛时把待补绘的段落补上。所有段落补齐后视为整间，画成一个完整轮廓。
- **地图**：
  - 区域地图只画已补绘的段落，地形轮廓按段裁切。
  - 公开房间未走过的部分保持底图色；隐藏、奖励类房间不画未走过的部分，不泄露房间尺寸。
  - 世界总览同样按段落绘制。
  - 房间内的钟龛、旧路标记、已见障碍和玩家图钉，只在已补绘的段落出现或可放置。
  - 房间计数按房间而不是段落计算。
- **兼容**：旧存档里整间已补绘的房间保持整间。查询段落时只读不改存档，格式错误的笔记一律当作未补绘。

## 代码

- `pilgrimage_cartography.gd`：`segments`、`visit_at`、`charted_parts`（只读）、`charted_whole`、`charted_at`、`charted_room_count`；`charted` 改为“房间任一部分已补绘”。
- `main_level.gd`：房间追踪改用 `visit_at`，传入玩家位置。
- `cartography_runtime.gd`、`world_atlas.gd`：按段落绘制，标记按所在段落判断。
- `survey_map_knowledge.gd`、`map_player_pins.gd`：障碍标记和图钉按所在段落判断。

## 验证

- 新增默认 CI 套件 `survey_room_segments`，27 项通过：
  - 规则：分段阈值、段落覆盖整间、2×3 大厅。
  - 记录与补绘：只记所在段、补绘前不显示、全部补齐合为整间、房间计数。
  - 旧存档整间保持整间；格式错误的笔记不补绘也不被修改。
  - 真实 World：钟梯井在顶段记录 → 补绘后地图只画四分之一高度；再走底段 → 两段；走完全部 → 整间；图钉和障碍标记只在已补绘段落可用。
- `cartography`、`survey_map_knowledge`、`map_player_pins`、`world_map`、`inventory_map` 通过；`npm test`（含执行器 123 套件的数量检查）通过；recovery-mode 双导入通过。
- `map_player_pins` 首次运行时遇到一次 Godot 4.6 dummy 渲染器的贴图初始化竞态（`Parameter "t" is null`，与地图逻辑无关）；本分支重跑两次与 main 上各运行一次均通过。
- 另用本机真实显示截图核对：钟梯井只走过上两段时，下两段只显示底图色、不带地形。
