# World departure snapshot preparation

This increment continues W00b2b from PR #63 (`2bed841`). The asynchronous travel path prepares its departure configuration and settled world-state rollback snapshots with the existing incremental variant copier. These two loader-level whole-tree copies are the scope; `_save_world`, world-state capture/validation, build serialization, JSON serialization and disk writes retain synchronous work.

The source stays resident while the snapshots are staged. A dedicated departure phase gates gameplay/input, preserves the loader generation until the existing unload boundary, and checks operation ownership and source identity across copy yields. A complete detached configuration/state pair is required before source audio, platforms and nodes are released. Cancellation or invalidation during snapshot preparation restores the live source in place rather than rebuilding it from incomplete staging.

A departure checkpoint can still be saved at the existing source-save boundary. This does not publish target rewards or progression. Failed capture or a real write failure must not admit travel with stale rollback data. An incompatible-save block retains the established in-memory travel behavior while withholding disk writes. Events that legitimately change source progression while copying invalidate the attempt and keep their live effects; they cannot be silently dropped or mixed into an accepted snapshot. Safe dirty-source aborts retry the source checkpoint after releasing the gate.

Copy begin/step work, edge/batch counts and yielded wall intervals are measured separately. The edge cap is an admission bound, not a hard duration or frame-rate guarantee. Private staging assumes production mutation paths respect the departure fence; arbitrary external deep dictionary mutation is outside that contract. Coordinate first read, save capture/validation/writes, build serialization, key enumeration and indivisible leaf work remain further synchronous costs.

The copy work metric covers copy begin/steps, with settlement/save and build serialization measured separately. Wall time is sampled before abort cleanup and a possible dirty-source checkpoint retry, so it does not represent the complete abort latency. Dirty-save attempted/succeeded fields identify the extra persistence attempt. Snapshot records survive later target construction or rollback metrics.

Implementation and independent read-only review used separate subagents. Root repeats the new suite and independently checks preflight, asynchronous loading, host ownership, interaction safety, death-cache flush and both neighbor-gameplay paths. Final results and source/log hashes are recorded in `artifacts/departure_snapshot/verification.json`. Full remote 97-suite integration CI remains a separate gate.

The initial check-only gate rejected two inferred Tween declarations in the new fixture; explicit types fixed them before scene execution. The first passage replay subsequently failed its unchanged movement/arrival assertions. A diagnostic replay established that the fixture itself repeatedly changed the player's process mode from the loader's disabled snapshot mode to inherit. The fixture must respect loader ownership during this new phase while retaining its original walk budget and assertions. Review also found that a successful snapshot must keep the settled handoff's unlocked input state, rather than restoring an old source-overlay lock into the next region; only an in-place abort restores the original source lock. Targeted overlay/rollback checks are included in final verification.

The overlay assertions were first run against the old lock-restoration behavior and correctly failed both rollback and successful arrival. The loader now leaves the settled handoff unlocked on commit, while in-place cancellation restores the source lock. The final clean suite retains those assertions. The passage fixture retains its original 3600-frame walk budget and all original movement/arrival checks; it only stops overwriting the loader-owned process gate during departure preparation.
