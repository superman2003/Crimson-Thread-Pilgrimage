# T05 发布检查：实际发布包的多槽与损坏记录保护

保留原发布包首启、续玩写回、退出诊断和ZIP校验门禁，再在独立临时用户目录运行实际交付的可执行程序。新增三个存档槽各自首启与续玩，核对实际碎钱、库存、构筑、剧情与归途结；每次只允许活动槽变化。先删对应旧备份，再要求真实续玩生成包含同一进度的新备份，防止被动退出或旧文件假通过。

两种损坏情况分别覆盖不完整JSON主档加有效备份，以及负碎钱的语义损坏主档加损坏备份。启动不得静默恢复、覆盖或另建临时记录；所有槽及备份/恢复旁证按原字节比较。随后第三槽仍须独立续玩并写回。明确--new-game时，要求活动旅途原字节保存为.previous，已有.previous另行保留，不改变其他槽。没有模拟设置里的恢复按钮，也不把保留坏档说成自动恢复。

输出逐启动日志和完成后才生成的save-contract.json；导出包构建清单标记新增门禁。每次仍严格检查进程退出、完整引擎错误输出及原600秒单进程时限；没有删除或跳过原测试，没有重试代码失败。Linux/Windows发布工作流均执行新旧门禁及其负例，新增路径自监听；npm test:export也运行新工具回归。
