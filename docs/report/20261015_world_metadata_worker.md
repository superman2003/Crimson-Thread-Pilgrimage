# World shared metadata worker preparation

This increment continues W00b2b after PR #61. The scope is the persistent World's asynchronous region preparation: its campaign, chapter, audiovisual, and item-lore jobs send cold and stale content reads/parsing through the loader's existing single configuration reader, and prepare cache/consumer ownership copies incrementally. Existing synchronous compatibility and non-World behavior remain available.

The existing cache contract is retained: metadata-source keys are canonical, freshness uses source modification time and byte length, valid empty dictionaries are cached, failures return an empty consumer value without poisoning the cache, and consumers cannot mutate cached snapshots. Cancellation and invalidated operation ownership are distinct from a valid empty or failed metadata result. Metrics retain cumulative probes, body reads, parses, bytes, and failures across travel and rollback.

Coordinate queries also stop defensively copying the whole layout for internal scalar/vector lookups; the public `manifest()` API retains its defensive copy. The initial layout read still participates in synchronous save validation, so coordinate-manifest startup I/O and the prepared region's handoff deep copy remain outside this increment. This does not change save initialization order or claim all startup work has a hard frame-time bound.

## Verification

The loader intercepts the four shared-metadata preparation job families, covering the existing eight source files. It canonicalizes each path, probes source length/time, and reuses a fresh cache entry. Cold reads wait for the existing reader ticket, then use the existing variant-copy job with at most 512 edges per step to create a detached cache snapshot. The worker-owned parsed source becomes the cold consumer value; a warm consumer instead receives a bounded detached copy of the cached snapshot. Cache publication and consumer handoff require a final source-state and operation-context check.

Metadata load/parse/type failure keeps the established nonfatal empty-value behavior, removes an obsolete cache entry, and permits a repaired source to be tried again. A valid empty dictionary is a successful cache entry. Cancellation, generation/route/startup-lease invalidation, and detach/free/shutdown return an incomplete-operation status and abort preparation rather than masquerading as empty metadata.

Per-job records distinguish cache hits from actual worker use, and record wait frames, worker time, copy begin/steps/edges, maximum step work, and wall time. The legacy preparation work total includes measured copy begin/step work, not all canonicalization, file-state probes, assignment, or waiting overhead. The surrounding synchronous admission-batch timing does not measure the entire metadata coroutine; use the independent copy and wall metrics. Cumulative cache counters keep their existing accepted-read/parse semantics; a cancelled/discarded physical worker read need not appear as an accepted result in those counters.

Coordinate helpers return scalar/vector/rectangle values or a fresh location dictionary from the private layout. Public `manifest()` callers still receive a defensive deep copy. Save migration/validation order is unchanged. The initial coordinate read, public manifest copies, prepared-region handoff deep copy, direct synchronous compatibility API, file-state probes, key enumeration, and individual indivisible operations remain outside this budgeted metadata path. Matching source time and length retain the existing limitation that same-stamp/same-length content replacement is not detected.
