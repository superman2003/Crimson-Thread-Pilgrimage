# 2026-10-15 路线配置复制与覆盖分帧

基于 PR #57 当前提交 `39e93ccc`，推进 W00b2b 配置准备。邻区预检现在把新读入的 JSON 配置深拷贝与世界路线覆盖纳入已有逐帧 validator：拷贝按最多512条边一批推进；覆盖把目标数组查询、字段写入、交互筛除、附加内容及嵌套值复制拆成有界步骤。overlay 内部按最多32个小操作或约1.2ms时间预算组成一批；每个操作之间检查预算。外层仍使用现有8项与2ms准入策略，单个引擎调用不能被抢占，2ms不构成硬帧时限。

同步 `ROUTES.apply_to()` 和 `WorldRegionLoader.validate_config()` 保留为旧路径。真实六区生产配置的完整验证结果逐区同时与旧同步验证结果和 `ROUTES.apply_to(raw)` 对照，均精确相等；输入 raw 与 manifest 快照隔离。回归覆盖manifest版本过期、首区/邻区预检取消及前台优先既有路径，并新增重复目标ID的全目标应用、空overlay无操作、门户与同名移除项、typed移除ID、宽字典覆盖、深层数组/字典值与来源隔离。

## 验证

Godot 4.6.1 / Mesa llvmpipe GL 下 `world_preflight_budget` 通过4290 checks、零失败。第一地区同步旧验证 CPU 为24.130ms，新增量验证为25.492ms；这是同进程同夹具CPU测量，不是端到端帧时间或FPS结论。该地区快照复制24批，复制批最大858µs；覆盖642个内部操作，覆盖批最大939µs。另一个合成宽覆盖包含96个世界边界键、65个重复目标房间、64个门户、交互筛除及64项嵌套目录：5380个内部操作分为169批，每批不超过32个操作，观测最大批497µs。

同一容器、同一引擎/GL方式与同一回归夹具的直接对照：39e93ccc基线445批/3.156秒/23.456ms validator工作时间；候选466批/3.301秒/78.528ms validator工作时间。批数增加约4.7%，夹具墙钟增加约4.6%；validator工作增加约55ms，主要是把原来一个整体overlay调用拆成可检查预算的操作。两次最大批时间分别为3.479ms与2.662ms，均说明2ms只是后续操作准入预算，单个validator.step与引擎操作不会被抢占。这是同环境压力回归夹具，不是玩家设备的完整启动/旅行时长。

仍有不可抢占调用：GDScript 对字典的 `keys()` 会一次枚举出键数组；单个512边复制批、单次字典键数组生成及单个嵌套值的构造都不能在调用内部让出。上述实测夹具的复制begin最大11µs；不能据此推断极端宽字典的耗时上界。文件读取/JSON解析和遗留同步 API 也不在本批改造范围内；本批只保证邻区生产 validator 的所述复制/覆盖工作受预算驱动。没有目标硬件帧率、长时稳定、自然通关或所有同步配置API均预算化的结论。

候选工作树初始资源检查因未hydrate字体/贴图失败；hydrate并完成两轮recovery import后复验。直接基线首次运行也因跨工作树复用import缓存报资源错误；完成两轮recovery import后同命令基线通过4020 checks，零错误。早期候选还发现并修复validator状态重启、空overlay版本写入、portal重复筛除、重复目标覆盖及typed移除比较问题。最终记录只计通过的检查；中间失败不计入通过数。
