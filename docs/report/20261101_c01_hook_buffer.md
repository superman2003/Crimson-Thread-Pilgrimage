# C01：掷钩键也有输入缓冲

接续 #487 留下的边界“掷钩键无输入缓冲”，起点为 main（含 #487）。所有 46 个任务包的最终验收仍开放。

## 改动前

普攻和冲刺按下后会进入 0.10 秒的动作缓冲，挥针收招、冲刺或欠收势期间提前按下，会在可以出手的那一帧执行；欠账长于缓冲时，缓冲会一直延长到还清。掷钩只在按下的那一帧检查能否出手：挥针收招中、冲刺末尾或 #487 的欠收势期间按下就直接丢掉。同样的连段里，普攻提前按有效，掷钩提前按却没反应。

## 现在

- 掷钩并入同一个动作缓冲。优先级为冲刺 > 普攻 > 掷钩，规则与普攻一致：最新指令替换待执行指令；收招、冲刺或欠收势结束后执行一次；超过 0.10 秒作废；按住不会自动连发；欠账长于缓冲时等到还清；受伤、打开界面等原有清空条件同样适用。
- 执行时仍先尝试钩索牵引，没有可用锚点再掷钩，判定与改动前相同；牵引方向在执行时读取当前上／下瞄准。

## 验证

- `player_action_buffer` 32→42 项（真实 InputMap 输入）：挥针收招中按掷钩，收招后掷出一次且不重复；欠收势 0.2 秒（长于缓冲）时按掷钩，还清后掷出；过早按下作废，按住不连发；之后再按普攻会替换待执行的掷钩；冲刺末尾按掷钩，冲刺结束后掷出；用冲刺取消收招并欠收势 0.3 秒时，在冲刺开头（0.16 秒，长于缓冲）按掷钩，冲刺和欠账都结束后掷出（审查意见：原先欠账延长发生在冲刺判断之后，冲刺中按下的掷钩会过期）。
- 反向：用 main 的控制器跑新检查，6 项失败；用修正前的本分支控制器跑冲刺开头那一项，1 项失败。
- `melee_recovery` 70 项通过（#487 的掷钩取消与欠账检查不受影响）。
- 相关套件见 PR 说明。

## 边界

规则与时序验证，不是手感验收。缓冲让掷钩更容易接在冲刺或取消之后，远程压制是否因此过强，需要 T04 判断。
