# B03：六位 Boss 的 24 招逐招开伤害验证

2026-11-02。台账 B03 的下一验收交付是“伤害开启验证六位独特招式与重试成本”。此前第二至五区 Boss 各有一条真实输入的整场回放，但只证明“打完了、用到了某几招”，没有逐招证明每一招真的会扣血、能躲、格挡规则对；第一区与第六区 Boss 更没有任何开伤害对战证据。

## 做法

新套件 `boss_move_matrix`（第一至三区）与 `boss_move_matrix_late`（第四至六区）。每区加载正式章节配置（`demo_chXX_*.json`），清掉杂兵，用正式 `_spawn_boss` 生成 Boss 并锁门，玩家为正式 `Player`（`debug_invulnerable=false`，HP 下降是唯一命中证据）。每一招都走 Boss 自己的 `_begin_attack` 起手→出招→收招路径；Boss 身体接触伤害在取样期间关闭，所以测到的是招式本身而不是走进 Boss。

每招依次做：

1. **站位取样**：玩家站在 Boss 身后 240px、身前 110/240/400/580px（落不到同一层地面的点记为跳过），站着不动，记录哪些点被打中。
2. **预警**：起手至少 0.55 秒，且每次起手期间都有可见预警（预警多边形、起手描边、Boss 技能预警图或尚未生效的地面危险）。
3. **躲避**：从最近的被打中位置出发，用真实按键 `move_left/right`、`jump`、`dash` 依次尝试后撤、前穿、原地跳、后撤冲刺、前穿冲刺、后撤跳，直到有一种完全不掉血。
4. **格挡**：在命中前 9 帧按真实 `bell_guard`。可格挡招必须被挡下（0 伤害），不可格挡招必须穿透。
5. **重试**：Boss 打到半血二阶段时玩家受致命一击；原 Boss 必须被回收、门锁打开，下一次 Boss 满血且回到一阶段。

另外从数据核对六位 Boss 的招式组合（类型＋可否格挡）两两不同；每位都至少有一招二阶段招式，且同时有可格挡与不可格挡招式。

## 发现并修复的问题：光束被玩家自己的身体挡住

“绯线封路”（第二区绯线执剪者）和“冠门封线”（第六区百钥守门人二阶段）在所有站位都打不到人。追踪光束发现长度总在玩家中心前约 17px 处被截断：光束检测墙体的射线用碰撞层 1，而正式 `Player` 的 `CharacterBody2D` 也在层 1——光束把玩家身体当成了墙。`_hits_player` 只判断光束长度以内，所以永远不命中。

同一函数 `_wave_wall` 也给地面波用（波先判命中再判墙，所以波仍能伤人，但会在玩家身体处提前消失）；光束创建时的初始裁剪 `enemy_actor._effect` 也有同样问题。受影响的光束招式共 5 个：两位 Boss 的上述两招，以及小怪的“近身蒸汽反喷”（`pipe_thrower`）、“排汽横扫”（`valve_crawler`）、“擦除直线”（`erasure_bailiff`）。

修复：`enemy_attack_effect.player_bodies()` 返回玩家组的刚体 RID，`_wave_wall` 与光束创建时的射线都排除它们。地形、岩体与静态体仍照常截断光束。`beam_channel` 套件新增一项：给测试目标加上与正式玩家相同的 34×84 层 1 碰撞体，光束必须仍以完整长度命中；去掉修复时这一项准确失败。

“交错根笼”是唯一站着不动不会受伤的招式：四个坑以玩家为中心、间距 120px 分布，最近的两个距玩家 60px，而坑的判定半径加玩家半径为 57px。套件把它作为“牢笼”招式单独验证——站定是躲法，坑生效后向任一侧迈步 18 帧就会受伤，所以它不是摆设。是否符合设计意图（逼玩家停手）需要人工确认。

每位 Boss 的重试：致命一击后原 Boss 被回收、门锁打开，下一次满血一阶段。演示宿主（Main）复生时会直接重新布置门后 Boss；正式 World 要回到钟门手动开战（`world_g02_death_playback` 已证）并扣一半碎钱（`world_bride_retry_playback` 已证），本套件不重复。报告中的 `boss_checkpoint_to_gate` 是配置里 Boss 检查点到钟门的直线距离。

## 顺带测得：HUD 每帧刷新约 7ms

测速时发现章节场景无头运行每帧约 13ms，其中 UI 外壳 `pilgrimage_interface._process` 约 7ms，主要是 `_refresh_combat_status` 每帧重建整个构筑快照（约 4.8ms）。本套件只读战斗状态，因此取样期间暂停 UI 外壳的 `_process`，单套从约 4.5 分钟降到 1 分钟以内。HUD 每帧开销本身留给下一批（T03/U03）处理，本批不改 HUD。

## 边界

- 站位与按键都是固定脚本，不是人工手感。“躲得开”只证明至少有一种真实输入能完全避开，不代表难度合适；招式节奏、读招难度与重试挫败感仍需人工试玩（T04）。
- 二阶段招式通过直接设置 `battle_phase=2` 取样，没有走完一阶段；阶段切换本身由各区整场回放覆盖。
- 碰撞接触伤害在取样时关闭；Boss 本体接触伤害沿用原规则，未在本批改动。
