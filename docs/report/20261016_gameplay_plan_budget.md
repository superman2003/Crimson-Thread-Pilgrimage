# W00b2b：邻区玩法候选计划分帧

基于 main `b8d6698504f52d53a2b6ceea87b78dc7f0610806`，只处理邻区敌人、NPC、钟龛和交互的候选选择与数据复制。该运行时文件在已发布旧 W00 链 `f696cb0`、main 和战斗资源分支 `8218f20` 上相同；本批不混入未进入 main 的旧功能链，也不依据旧任务摘要重建未取得的路线索引补丁。

## 实现与契约

原 `world_gameplay_prefetch.synchronize()` 在共享预算检查前扫描全部记录，对每个候选深拷贝、整表排序后截断。现在同步入口只捕获配置租约；`warm()` 在既有 2ms 准入窗口中每次最多推进 32 个计划操作：

- 每操作扫描一个记录，分别保留敌人4、NPC3、钟龛2、交互3个最近候选；比较仍是距离平方优先、同距按键排序。
- 最多12个入选项按原分类顺序合并并使用同一最终排序；仅入选项通过现有显式栈复制器逐步复制，每个复制操作最多64条边；32次操作的静态最多复制边为2,048，逐操作仍检查同一共享2ms截止，并非一次执行32步后才检查。
- 计划全部完成且租约仍匹配后，才一次发布 pending 列表。`plan_complete` 明确区分“尚未规划”与“已经规划且无待建对象”。
- 代数、入口、路径、文件时间戳、配置记录及 raw/prepared 快照身份变化，离开预取范围或退出时取消私有计划；过期计划不能创建对象或被到达流程采用。
- 几何与角色共享每帧最多2项创建/退休、角色含待退休总数最多24的既有约束不变。预建节点仍在树外，抵达后绑定真实世界状态。

审查发现原验证器在路线覆盖前检查 ID，覆盖后仍可能产生同键、同距但负载不同的条目。Godot 的大数组排序不稳定，直接稳定限量插入会改变这些已被接受配置的顺序。现在只有可能进入入选集合的重复比较键触发兼容路径：逐条重扫对应类别，然后对候选引用使用完全相同的旧排序和截断；不先深拷贝全部候选。该兼容排序仍是不可抢占的单项，单独记录候选数和耗时，作为 W00b2b 的剩余边界。普通唯一比较键路径仍只保留至多12条候选。

同一反例暴露了原预建缓存按 key 覆盖时丢失旧树外节点的问题。本批在新节点创建成功后，将同键旧节点放入既有退休队列再替换槽位；保留最终后写条目的采用语义，旧节点在真正释放前继续计入24项所有权上限。

同步 `plan()` 保留原样，作为输出顺序与数据的对照。新增计划/扫描/复制工作量、完成/取消次数及单操作时间指标；不把跨帧次数当作帧率。

## 验证范围

专项覆盖六区配置、全部68处已有门户落点及六处出生点，空配置、边界窗口、排除类型、同距排序、实际被验证器接受的覆盖后重复条目、跨字段同键、12,000候选、深层负载、取消和源租约变化。针对深层 JSON 的精确比较用显式栈，避免 Godot 自身递归比较上限掩盖结果。原邻区准备、正常伤害双向步行和六区美术对照增加显式规划完成判断，保留原业务断言与可见角色要求。

测量仅说明此环境中同步整批与增量操作的工作形态；小型配置的增量总 CPU 可能更高。2ms 是下一项是否准入的预算，兼容重复比较键排序、单个 `keys()`、复制器内部容器操作、文件元数据读取、引擎预建与敌人 profile 复制仍不可抢占。本批不承诺单帧硬上限或目标硬件 FPS。

### 专项测量与反例

官方 Godot `4.6.1.stable.official.14d19694e` 严格 headless 纯逻辑运行：`WORLD_GAMEPLAY_PLAN checks=1218 failures=0`，无引擎或脚本诊断。保持旧同步 `plan()` 不变，逐条、逐字段、逐序比较，不忽略重复键载荷差异。代表测量如下，单位均为微秒：

| 场景 | 旧同步整批 | 新计划操作累计 + begin | 最大单操作 | 其它证据 |
| --- | ---: | ---: | ---: | --- |
| 74个真实出生点/门户落点 | 8,786 | 39,116 + 169 | 446 | 六区、68门户落点、无兼容回退 |
| 12,000候选 | 189,420 | 110,009 + 6 | 1,858 | 12,019片、只保留4项、复制72边 |
| 深层负载 | 25,850 | 91,722 + 4 | 673 | 691片、复制40,536边 |
| 四类别重复比较键 | 2,154 | 3,163 + 3 | 兼容排序118 | 4次兼容排序、最大40候选引用 |
| 已接受覆盖加64条填充 | 749 | 1,505 + 4 | 兼容排序319 | 1次兼容排序、68候选引用、重扫87记录 |

这些单次数字不是硬上限；小配置和深层负载的总 CPU 明显增加，收益是把候选工作移入可观察、可取消的分片。同一32步版本的独立纯逻辑复验曾测得真实落点单操作2,298µs、深层负载5,107µs，明确超过2ms，故不据上述较小值宣布硬帧预算完成。兼容路径候选引用内存是 O(n)，不能据普通路径至多12项推断全路径恒定内存。

两项隔离 mutation 均执行到夹具结束、无解析/初始化失败：禁用快照身份租约检查触发21项失败；禁用重复比较键兼容检测触发14项失败，包含28/40/64填充的已接受覆盖精确顺序反例。两项在加入重复节点所有权修复并选定32步后隔离复验，仍分别21/14项失败；随后运行时仅澄清一处准入预算注释，当前最终源码另经完整验收。各自源码与日志哈希分别记录，不把注释前哈希称为最终提交。额外禁用旧节点退休的故障探针先触发1项所有权断言失败，随后夹具读取缺失旧节点产生1项 null 脚本错误；它证明故障会被拒绝，但不计入上述无脚本异常的完整 mutation 证据。独立审查另用1,200组重复键随机夹具（2,618次兼容排序）与100组低于截断线的重复项检查旧结果一致性；这些是额外审查证据，不替代仓库默认专项。
