# T03：将缩放字体限制在地图内容，固定控件复用 HUD 字体

定向诊断将冷启动 `_setup_cartography` 约 107ms 的耗时分到商人、召回和图钉控件，实际大头是图钉控件首次创建：109,125µs；地图面板另有 68,635µs。整个地图面板此前都继承 MSDF 字体，因此不缩放的标题、按钮和长提示也会生成另一套中文字形缓存。

本批将共享 MSDF 字体放到 `map_draw_root`，让图钉、世界区域名等实际缩放内容继续使用；固定屏幕位置的标题、图钉工具栏和底部提示沿用正常 HUD 字体。字体文件、字号、控件、地图投影、1–4 倍缩放与操作流程保持原值；所有控件仍在发布区域之前建立，没有把创建工作延迟到打开地图时。原共享缩放字形缓存跨区域复用的断言保留，并改为检查真正缩放的内容节点。

相同定向观察脚本和子类包装，新进程、原生 Godot 4.6.1 / NVIDIA GL 对照：初次图钉控件 109,125→6,849µs，地图面板 68,635→10,875µs；商人 4,984→5,295µs、召回 1,284→1,224µs，符合来源定位。这些是单项耗时，不能当目标机器的帧率承诺。

完整固定 QA 对照为 `d6ddc62dddb830ba8ba163d1adde706db814b54f` 与仅增加字体作用域改动的 `ece2f6de607f56cce018c47cd2d7ad8eb68cbfa5`。同一份六区诊断脚本，两者均三循环、21 次切区、3 次死亡、63 次界面操作，最后孤立节点和声部均为零，无 ERROR 或 warning。必须保留反向结果：整段最大采样帧间隔由 153,701 变为 184,688µs，后者在区域构建 cursor 28；本批没有证明整体最大帧改善。World PackedScene 初载约 1.1–1.2 秒仍然存在，且不包含在该过程帧间隔采样中。

两次性能运行都没有其它本机 Godot 进程，未清空系统或导入缓存，也未控制全部系统后台负载。QA 组合含 #173 的落点搜索和之前的主角预热原型，整体源码与当前 main 不同；四份相关地图/字体函数与最终分支逐字相同，比较脚本、原始指标、单项补丁及哈希已归档，不混同原型和最终版本。

初轮六套真实 GL 断言通过：带捕获的图钉 153 项、补绘 4,229 项、地图知识 43 项、世界地图 673 项、六区异步切换 492 项和界面整合。图钉、补绘、异步切换和界面整合各留一次 ObjectDB 退出警告，原日志保留。严格两轮导入在该轮初始基线通过。随后接入已含 #168/#170/#172 的 main `f26b9c2d0686d61d3982274f81987fb6cc12be1e`，固定源码 `56c28d276f31d85377430ad973e34ce8c28ba14f` 复验图钉 150 项和六区异步切换 492 项，退出均零警告；不能把上游资源所有权修复的效果归给字体改动。该组合 npm test、campaign 通过，Windows 原有 POSIX 夹具的跳过不记为实际执行通过。

新增检查分别验证固定按钮/标题/说明用正常字体，实际图钉保留 MSDF，以及缩放只改变内容而不移动工具栏。反向恢复旧的整面板字体后，恰好这两条固定控件字体断言失败，保留预期 ERROR；实验后生产源码已逐字节恢复。没有新增默认套件或放宽门禁。

用现有图钉操作/重启夹具扩展实际 GL 捕获，比较区域、世界总览和四倍区域图；[正常区域图](../../artifacts/t03_map_font_scope_visual/region.webp)、[世界总览](../../artifacts/t03_map_font_scope_visual/world.webp)、[四倍区域图](../../artifacts/t03_map_font_scope_visual/region_zoom4.webp)及旧字体对照均已目检。固定工具栏不随地图变大，缩放文字保留。限定四倍地图视口裁剪像素一致，两个一倍视图有少量差异，不宣称全图像素一致。它们是已补绘、暂停角色、合成输入的测试画面，不是自然流程或实体手柄验收；截图先于 main 整合，具体源码哈希在各自 manifest 中保留。
