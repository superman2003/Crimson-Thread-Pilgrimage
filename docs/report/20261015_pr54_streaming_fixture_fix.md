# PR #54：分帧预取旧任务测试修复

日期：2026-10-15。修复基线为 `a4487346f633a3ae0fc5ed8ad2be89fb20072e20`，继续更新同一 PR。

## 失败与根因

[基线运行时 CI](https://github.com/superman2003/Crimson-Thread-Pilgrimage/actions/runs/38593696715/job/115954843042)执行80套，79套通过，唯一失败是 `world_streaming` 的两条断言：没有准备好尚未接收的纹理请求，以及未观察到旧代数纹理结果被丢弃。前次修复的80轮邻区压力套件已通过，双平台桌面 CI 也通过。

旧夹具切到书库后仅等待2秒，假定配置同步校验完即可产生纹理请求。现在后台读取后每帧最多推进8步配置校验，纹理必须等配置完整发布才能准入。因此慢帧调度下，准备期限先结束，切区取消尚在校验的配置任务，自然没有可丢弃的纹理任务。

本地原脚本正常速度通过；同一 Godot 4.6.1 / llvmpipe 下使用 `--max-fps 30`，稳定复现与远端相同的两条失败。该限帧仅用于复现调度条件，不是目标硬件性能证据，也未加入 CI 运行器。

## 修复

旧任务夹具与首次邻区预热共用8秒准备上限，等待实际配置完成并由生产代码准入真实纹理请求。一旦出现请求立即停止推进，保留未接收状态，随后实际切区。

保留必须存在请求的原断言，新增请求属于已验证离开代数、切区推进代数、所有捕获请求排空、丢弃计数相对切区前的增量，以及到达缓存中不存在旧纹理的检查。切区后最多非阻塞轮询2秒，让尚在引擎中加载的请求完成；不会直接伪造任务或丢弃计数。

运行时代码、每帧8步和2ms准入、80套列表、压力80轮、每套180秒上限、实际GL绘制及 `ERROR` / `SCRIPT ERROR` 门禁均保留。

## 本地验证

Godot 4.6.1 / Mesa llvmpipe 实际 OpenGL，使用原运行器默认180秒：

| 套件 | 检查数 | 结果 |
|---|---:|---|
| world_streaming | 2549 | 通过，真实请求及逐个丢弃 |
| world_neighbor_config | 85 | 通过 |
| world_config_background | 38 | 通过 |
| world_async_loading | 424 | 通过 |

修复脚本在独立30 FPS复现场景下也通过2549项；实际准备耗时3841ms、真实请求1个，明确超过旧2秒窗口。正常速度准备耗时1429ms，同样捕获并丢弃1个真实请求。

`npm test`、`npm run test:campaign`、两轮恢复模式资源导入和本次5个文件的 `git diff --check` 通过。四套中 streaming、neighbor_config、async_loading 有 ObjectDB 退出警告；原有警告保留，未豁免引擎错误。资源导入不包含编辑器插件验收。

本地未重跑完整80套；新提交远端运行时和桌面 CI 单独核对。限帧夹具、来源冻结和人为切区不等同于自然六区通关、长期内存稳定或目标硬件帧时间验收。前次压力修复证据保留于 [20261014_pr54_stress_fix.md](20261014_pr54_stress_fix.md)。
