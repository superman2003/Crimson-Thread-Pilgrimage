# C01：掷钩收招也可被跳跃／冲刺取消，欠下的收招照样要还

接续台账 C01 留下的开放问题“掷钩是否也可取消”，起点为 main `e56ff5c1`。所有 46 个任务包的最终验收仍开放。

## 改动前

#227 让普攻（`attack_1`／`attack_2`）的收招可被跳跃、蹬墙跳、二段跳或冲刺打断，跳过的收招记为 `attack_cancel_lock`，还清前不能再出手。掷钩（`hook_throw`，0.42 秒：起手 0.06、判定约 0.22、收招约 0.14 秒）被明确排除，整段期间跳跃与冲刺全部锁死：远距离钩中敌人后只能原地站完收招，和普攻的手感不一致。

## 现在的规则

- 掷钩与普攻同一规则：起手与判定帧照常承诺，判定帧结束后的收招可被跳跃、蹬墙跳、二段跳或冲刺立即打断。
- 代价不变：剩余收招记入同一把 `attack_cancel_lock`，还清前不能再挥针、掷钩或施放线术；锁内按下的普攻留在缓冲、还清后出手，所以“掷钩→跳跃取消→下一击”的间隔不短于掷钩原本的 0.42 秒，换到的只有位移与躲避。
- 线术（`active_skill` 非空的重挥）仍保留完整收招，不能取消。
- 唯一代码改动是 `player_controller.gd` 的 `_attack_recovery_cancelable()` 把 `hook_throw` 加入可取消列表；钩索牵引（`_try_start_grapple`）本来就不是攻击，不受影响。

## 验证

- `melee_recovery`：原 56 项保留（原“掷钩保留完整收招”一项改为新规则），新增 14 项，合计 70 项通过（`--fixed-fps 60`，真实 InputMap 输入）：掷钩由真实 `hook` 按键发出；判定帧按跳跃不取消；收招按跳跃离地、按冲刺实际位移；欠下的锁不超过剩余收招；锁内再按掷钩不会出手；锁内普攻停在缓冲并在还清后出手；从掷钩到下一击的间隔不短于 0.42 秒；线术在收招按跳跃仍不取消；重置清锁。
- 反向检查：把 `hook_throw` 移出可取消列表，`melee_recovery` 7 项行为断言失败（收招段到达、跳跃取消、欠账、锁内不再掷钩、锁内普攻等待、冲刺取消，以及线术断言因前序状态不同而失败），不出完成标记。
- 相关套件：`player_action_buffer`、`player_melee_feedback`、`spike_pogo`、`combat_resource_cycle`、`ability_movement` 通过。

## 边界

这是实际输入下的规则与时序验证，不是手感验收。掷钩键本身没有输入缓冲（与改动前相同），欠账期间按下的掷钩会被忽略而不是延后出手；是否给掷钩加缓冲、收招长度与取消是否让远程压制过强，需要 T04 实机试玩判断。
