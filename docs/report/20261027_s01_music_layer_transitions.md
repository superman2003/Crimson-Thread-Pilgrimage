# S01 音乐叙事：乐句叠加与遭遇切换

对应修订台账 S01「转场不频繁重启，战斗层变化克制」子项。
本轮第 10/40 个独立台账升级；基于 main a3a5f95。

## 实际缺口与改动

探索音乐已有跨房间乐句记忆，本次沿用。旧战斗层从 0 秒播放，
即使探索层已在乐句中段，六区都会发生节拍错位。新相位函数读取
实际 AudioStreamPlayer 与 AudioServer 混音时钟，在下一次混音边界
加入目标循环；处理目标长度取模、播放倍率、停止/暂停/退役来源。
两轨共用输出队列，不重复扣除设备输出延迟。

Boss 入场现在清除普通遭遇逻辑状态，普通敌人轮询不能在 Boss 期间
预占一个没有播放的战斗层；离开 Boss 后下一次普通遭遇正常启动。
不播放模式也执行相同的状态释放，不会意外创建声部。

钟龛摇篮曲等待原有四秒脱战窗口；新威胁解除摇篮曲并恢复探索。
安静后进入钟龛会收掉尚在淡出的旧战斗层。沿用原有交叉淡化、增益、
三乐章、用户音量、场景归属与原生音频退役规则。

## 验证

- Godot 4.6.1，真实原生 Dummy 音频混音线程。
- 新增契约最初在旧生产实现中得到 214 项检查、30 项失败；
  修复后该集合 214 项全部通过。
- 扩展场景归属、轮询与用户偏好覆盖后最终 345 项全部通过。
  包含原有音量 37 项、声部预算 46 项、总线拓扑 21 项。
- 六区实际探索/战斗 Ogg 从中段叠加，混音相位差小于 0.12 秒；
  原播放器、缓存、总线与淡出中再接敌的 playback 身份保持。
- 六位 Boss、终 Boss 三乐章、Boss 后接敌、钟龛请求延迟、
  非驻留敌人、返回巡逻、重叠 Director 与音量静音均有覆盖。
- 真实退役屏障全部 pending=0，没有忽略原生错误。
- 独立工作流每次导入/运行保持 120 秒单项时限，退出码、
  ERROR/SCRIPT ERROR/USER ERROR 与正数检查成功标记必须同时满足。
  Python 自测用九种输出/退出码组合检查失败传播。

仓库完整 `npm test`、`npm run test:campaign` 以及分片/工作流九项检查通过。
本次八文件，528 行非文档改动（含测试与 CI，不含继承的前置改动）。

这是组件级真实音频播放验证，尚不等于耳机/扬声器实听、陌生玩家
自然流程或 S01 所有作曲与叙事动机的最终验收。远端 CI 另按新头核对。
