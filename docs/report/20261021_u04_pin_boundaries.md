# U04：密集图钉留在地图纸内，远移标签指向真实落点

正式六区地图的房间角落可以合法放入十二个间距 25 世界像素的图钉。旧布局只避开其它标签，没有检查地图纸边界；用实际 `UI.refresh`、实际字体和 `Label` 最小尺寸检查，639 组合法区域图夹具中有 128 组文字框出界。另有字体测量偏差：19 号实际字体单行约 27.7px、四行约 119.8px，旧碰撞框只按 26px／104px 计算，会低估合并号码的高度。

本批把实际字体最小尺寸用于排布，候选位置限制在固定地图内容矩形内；每次尝试只测量一次当前标签，已排标签的矩形缓存到该轮结束。地图投影、记录坐标、十二个容量、合法性、购买／补绘认知与写盘事务沿用原规则。区域图与总览都由原刷新入口执行该布局。

62 个地图像素继续作为优先偏移距离。过密的边缘号码必须全部可读时，合并标签可能超过它；正式夹具中普通号码有 38／1,278 组、大编号旧记录有 211／1,278 组使用超距摆放，不能声称每个标签都在 62px 内。超距号码各有一条细引线，从真实投影点连到标签固定指示点；每次刷新最多十二条，随地图缩放、平移与重建一起变化。真实落点落在大标签内部也保留引线。

原地图知识套件复用一次正式 World，增加六区 639 组合法房间角落 × 区域／总览 × 普通／有效旧存档大编号，共 2,556 组。检查独立读取 `Label` 实际尺寸，验证纸内完整、不重叠、每个号码与删除列表 ID 恰好一次、原落点与序列值不变、真实引线两端与数量，以及普通和旧编号都确实生成引线。检查还保留 checkpoint 对象／值、正式存档和备份逐字节一致。默认套件数量未增加，专用 CI 加入新 helper 与知识套件文件的触发路径。

最终源码三文件哈希对应已推送代码提交 `15538cf3c1d4db5ddeebfbef69e07021fe0b7598`，四套 Godot 4.6.1 原生 NVIDIA GL 均完成：地图知识 190、图钉 146、世界地图 673、补绘 4,229 项，零 ERROR。前两套各有一条 ObjectDB 退出警告，后两套没有；完整日志保留，不记作 T03 退出问题已解决。npm test 与 campaign 通过，既有 Windows POSIX 跳过仍不算实际执行通过。

反向检查分两种：恢复 main 原完整运行时，边界／实际行高／落点指示断言拒绝；只移除引线刷新调用，保持纸内布局，真实引线和非空覆盖断言拒绝。预期失败单独归档，生产文件均逐字节恢复。最后的源码哈希与提交对象再次核对。当前图像与断言不构成目标机器 FPS、整包或长跑验收。
