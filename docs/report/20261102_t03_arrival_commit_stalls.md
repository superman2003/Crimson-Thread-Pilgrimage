# T03：到达提交阶段不再为很少打开的窗口排版

接续 #498 的测量：传送／读档时，构建阶段之后最大的单帧在“到达提交”阶段（整理行囊、设置、地图等界面）。起点为 main。所有 46 个任务包的最终验收仍开放。

## 改动前

每次切区都会重建界面外壳，提交阶段按任务分帧，但单个任务不可再分。逐段计时（真实 GL，六区传送）：

- `_build_bag`（行囊页）95–306ms，其中：旅记工具条（搜索框、两个开关、排序菜单）25–35ms——这些控件先设文字再入树，每个都在树外排一次版；`journal_find_dialog.install`（本条查找窗口）25–35ms；`resource_purpose_dialog.setup`（资源用途核对窗口）35–55ms。后两者是很少打开的独立窗口，却在每次到达时完整排版。
- `_build_settings`（设置页）45–64ms，其中 `audio_output_dialog.install`（声音输出设备窗口）约 20–25ms。

## 现在

- 资源用途核对、本条查找、声音输出设备三个窗口：节点和入口按钮照常创建（其它代码与测试按名字找得到），窗口内容在第一次打开时才建。窗口里的刷新／查找／切换函数在内容未建时直接返回。
- 旅记工具条改为先入树再设文字和菜单项，与 10-21 批次对其它控件的做法一致。

## 验证

- `ui_text_order` 9→17 项：三个窗口在 World 就绪后没有内容、首次打开后建好并填好数据；重建行囊时旅记搜索框、开关、排序菜单入树时仍为空。反向：换回 main 的四个文件，新增 8 项中 6 项失败。
- 打开这些窗口的既有套件通过：`journal_find` 34、`journal_find_world` 24、`pickup_ledger`（含资源用途核对）174、`thread_budget_world` 17、`audio_output` 48（隔离契约 `run_audio_output_contract.py` 同样通过）、`settings_dialog_layout_world` 24、`dialog_viewport_fit` 110（42 个对话框）、`ledger_20261028_10` 20、`journal_desk` 40、`ui_redesign`、`ui_world_integration`、`world_async_loading`。

## 边界

相机观察窗口（8–17ms）引用较多，这批没有改。提交阶段剩下的较大任务是设置页其余控件、`_setup_cartography`（25–38ms）和首次进入时的 `append_inventory_item`。固定夹具测量，不是自然游玩帧率。
