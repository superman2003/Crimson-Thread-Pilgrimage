# T03：传送与读档时目标区域的两个大卡顿任务

接续台账 T03“隔离帧时间”与 11-01 的测量（传送、快速旅行、读档时单个构建任务可达 0.4 秒）。起点为 main。所有 46 个任务包的最终验收仍开放。

## 改动前

走路跨区时，`world_prefetch` 会在接近边界时提前读入下一区的大贴图；传送、快速旅行和读档不经过边界，构建阶段在主线程上同步读图。分帧构建里最重的两个任务是：

- `_background_art`：远景 `background.png` 与装饰图集 `decor_atlas.png` 各约 100ms，同步解码，整个任务 100–146ms。
- `_background_cave`：岩体外露边与岩体分块计算。`cave_rim_geometry.exposed()` 对每块岩体扫描全部岩体（n²），`visible_rock_mass.configure()` 再对每条外露边把全部岩体片段做一次矩形减法（边数×片段数），苔钟庭 282 块岩体、334 条外露边时约 0.18–0.46 秒（冷启动更高）。

## 现在

- **目标区域贴图预热**：构建阶段开始前，加载器在工作线程读入目标地区主题的五张大图（与 `world_prefetch.TEXTURES` 相同），读完并持有后才开始分帧构建；已在缓存里的直接持有。等待期间每帧只轮询，不阻塞；过渡取消时放弃结果，整体关闭时回收线程。headless 下按既有规则在主线程就地读取。
- **岩体几何建索引**：外露边与岩体修剪改为按 512px 网格只取附近的岩体／修剪带。每块岩体按外露边原顺序独立修剪，再按原岩体顺序拼接，所以得到的片段和顺序与原全量扫描完全相同。
- 加载器在每次过渡的指标里记录最慢的构建任务名和耗时（`max_build_job`、`max_build_job_usec`）、`background_art_usec`／`background_cave_usec`，以及各阶段的最大单批，下一个卡顿点不用再临时插桩。

## 测量（真实 GL，`world_async_loading` 夹具六区依次传送，各两遍）

构建阶段最慢的单个任务（ms，两遍）：

| 地区 | 改动前（任务） | 改动后（任务） | `_background_art` 前→后 | `_background_cave` 前→后 |
|---|---|---|---|---|
| 苔钟庭 | 268／190（cave） | 67／81（练习靶、敌人） | 112／87 → 2／2 | 268／190 → 33／49 |
| 铸雨渠 | 166／169（cave） | 72／66（敌人） | 113／136 → 5／2 | 166／169 → 39／42 |
| 盐白书库 | 139／132（art） | 39／42（地基、练习靶） | 139／132 → 11／3 | 40／37 → 27／19 |
| 断弦温室 | 120／126（art） | 31／28（敌人、cave） | 120／126 → 6／6 | 52／40 → 14／28 |
| 黑曜巡礼道 | 105／124（art） | 83／109（收集物） | 105／124 → 2／5 | 60／56 → 19／26 |
| 无声王冠 | 102／118（art） | 24／19（cave） | 102／118 → 5／2 | 86／52 → 24／19 |

“改动前”为 main 的岩体几何并关闭贴图预热，其余代码相同。

加载器原来只有一个跨阶段的 `max_batch_usec`；本批按阶段分别记录（`max_unload_batch_usec`／`max_build_batch_usec`／`max_commit_batch_usec`）。改动后再跑一遍：构建阶段最大单批 16–74ms，卸载 17–27ms，**到达提交阶段 95–306ms**，是现在每次传送最大的单帧，所以整体 `max_batch_usec`（120–240ms）没有下降。

## 验证

- `world_rim`：新增与原算法逐字比对——六区正式岩体数据和 6 组随机岩体（重叠、相邻、完全重复、跨多格的 4096px 长条、负坐标）上，外露边和修剪后的岩体片段（含顺序）都与保留在测试里的原全量算法一致。10170 项通过。反向：去掉网格候选的排序，四个地区的修剪结果不一致；把查询范围缩进 1px（漏掉恰好相邻的岩体），多个地区各 8–14 项“外露边面向空气”失败。
- `world_async_loading`：每区检查目标主题贴图在构建前全部持有、无读取失败，构建后仍在缓存中；504 项通过（headless 与真实 GL 各一遍）。
- `world_streaming`、`world_host`、`world_material`、`cave_collision_streaming`、`cave_exploration`、`cave_route_walk` 通过。

## 边界

只处理了构建阶段的这两个任务。现在每次传送最慢的一帧在到达提交阶段（95–306ms）；构建阶段剩下的是单个敌人生成（30–80ms）、练习靶、收集物（最高约 110ms），都留给后续批次。测量是固定夹具里的传送，不是自然游玩帧率；走路跨区原本已有边界预读，不受影响。
