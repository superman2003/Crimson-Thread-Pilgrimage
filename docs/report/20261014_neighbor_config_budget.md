## 行为与所有权

此前靠近出口时，`world_prefetch.step` 会在主线程同步读取邻区JSON，并一次执行完整验证。现在邻区借用 `WorldRegionLoader` 所有的 `WorldConfigReadJob`。整个宿主仍最多持有一个配置文件工作线程/未接收结果；原有纹理后台请求另外维持最多两个。工作线程继续只访问私有文件与JSON数据，不操作场景树、玩家、共享缓存或路线状态。

邻区请求至少经过一次后续 `step` 才接收结果。主线程复用同一个 `WorldConfigValidator`，每次 `step` 最多准入8个校验步骤，与退休、纹理和对象预建共用2ms准入预算。读取与部分校验结果由一个任务私有持有；全部通过后，再检查来源代数、目标地区、路径、入口与文件时间戳，一次发布raw/prepared记录，然后排入纹理和预建。

正式切区先取消邻区票据并接管同一个reader。仍在读取的任务不能强制终止，切区沿用已有逐帧等待，在它结束后才启动新的读取。已完成但未取回的合法票据也不能被第二次 `request` 覆盖；取消必须匹配票据。邻区仅废弃自己的暂存数据，loader在宿主退出时负责最终drain/join。`prefetch.shutdown`保留原有可清理后重用的语义，不关闭借用的loader服务。

离开范围、入口/路径/时间戳变化或代数变化都会废弃暂存校验。失败配置保留空raw失败记录，避免每帧反复读取/报错；对应租约变化后会重试。发布前的异常不授予物品、修改世界进度或写存档，也不会把邻区错误写入前台 `loader.last_error`。

可观察指标包含 `config_pending`、`config_phase`、取消次数、总校验步数/批次数、上次/最多准入步数、最大单步耗时、各类操作累计耗时，以及工作线程耗时、字节数和线程身份。指标累计于prefetch宿主生命周期；不能据累计时间直接推断某一帧CPU或FPS。
