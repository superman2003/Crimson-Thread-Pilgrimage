# W05：十二条捷径在任何能力组合下都不会绕过能力门

2026-11-04。台账 W05 的下一验收交付是“通勤耗时、实体设施、不能绕能力门”。现有 `world_route_access_validation` 只逐个传送门检查“能力条件与单向闩互不替代”，没有把整个世界连起来看：如果某条捷径的拉杆放在一段单向下落之后、门的另一侧却是要冲刺才能进的房间，玩家不带绯线冲刺下落、拉杆，就能从捷径进去。这类问题只有放在全图里才看得出来。

## 做法

新工具 `tools/audit_shortcut_bypass.py`，把六区连成一张房间图：

- 各区作者写好的房间连接：通道、单向下落、能力门（记所需能力）、拉杆捷径（拉杆所在房间由坐标判定）；
- `world_routes.json` 的 68 个传送门（区间通道与工房内升梯）：所需能力、单向闩（`requires_shortcut`）、走过即打开闩的一侧（`unlock_shortcut_id`，与 `main_level` 中通行时写入闩的代码一致）；
- 20 处能力回访工房的奖励：从工房进入奖励需要该能力。

对 8 种移动能力的全部 256 种拥有组合，从新游戏起点算两次可达房间：所有捷径关闭；以及捷径一到达开启侧（拉杆房间或开闩传送门）就打开。第二次多出来的任何房间都是“捷径绕过了能力门”。

自测 `tools/test_audit_shortcut_bypass.py` 已加进 `npm run test:campaign`。它会人为植入两种绕门写法：拉杆放在下落坑里、闩门通往冲刺房；开闩传送门通往要回声钩索的房间。两种都必须报出绕门。拉杆放回门内侧（只作回程）时则不得报错。

## 结果

256 种组合下绕门 0 处，全部房间在拥有全部能力时可达，12 条捷径都能被打开。各捷径在“刚够打开它的能力”下节省的房间步数：

| 捷径（游戏内标签） | 两端房间 | 开启时最少拥有 | 关闭时 → 开启后（房间步） |
|---|---|---|---|
| 旧运书线（苔钟庭 ↔ 盐白书库） | entry_bell ↔ candle_mezzanine | 双线跃、丝壁攀附 | 7 → 1 |
| 苔钟庭 后门升梯拉杆 | sluice_hall ↔ bell_stair_well | 无 | 不可回 → 1 |
| 铸雨渠 水轮捷径控制器 | wheel_shaft ↔ spillway_ladder | 无 | 不可回 → 1 |
| 盐白书库 战斗门控制器 | salt_gate_walk ↔ atrium_shaft | 丝壁攀附 | 16 → 1 |
| 断弦温室 战斗门控制器 | west_spoke ↔ west_gate | 丝壁攀附 | 10 → 1 |
| 黑曜巡礼道 战斗门控制器 | funicular_shaft ↔ pilgrim_camp | 丝壁攀附 | 4 → 1 |
| 无声王冠 战斗门控制器 | ring_west ↔ crown_antechamber | 灯影相位、丝壁攀附 | 5 → 1 |
| 旧补给索道（铸雨渠 ↔ 黑曜巡礼道） | wish_board_landing ↔ pilgrim_camp | 丝壁攀附 | 不可回 → 1 |
| 苔钟庭 盐风归庭索道 | entry_bell ↔ salt_corridor | 双线跃 | 1 → 1（房间层面无节省，省的是房内攀爬） |
| 三处深井返程升梯（苔钟庭、盐白书库、断弦温室下劈工房） | 同一工房内 | 无／丝壁攀附 | 0 → 0（省的是房内攀爬） |

“不可回”表示捷径关闭时从开启侧走不回另一端，捷径正是下落区的回程。

## 边界

- 检查的是作者写好的房间图，不是物理路径；每条连接能否实际走通由路线行走套件负责。
- 能力按任意组合考虑，不模拟取得顺序，所以不判断“会不会被困”：例如铸雨渠的下落区要靠本区取得的丝壁攀附才能出来，在“什么都没有”的组合下看起来像死路，其实不是。
- 通勤耗时只给房间步数；实际秒数与升降设施手感仍需实机（T04）。
