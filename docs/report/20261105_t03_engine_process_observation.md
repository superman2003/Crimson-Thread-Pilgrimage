# T03：采样真实引擎进程，结束完整 Windows 启动树

Windows 的 Godot console 可执行文件会启动独立引擎子进程。旧长跑工具以 Popen.pid 采样，实际量到启动器：一次原生设置专项的进程观测为启动器 6,971,392 字节、真正引擎 441,573,376 字节。两者父子关系和实际命令已记录；此前 Windows 启动器 RSS 不应解释为游戏驻留内存。Godot 自身静态内存、节点、音频及 Linux 数据须按各自原始证据区分，不把这处 RSS 错误扩展成所有旧指标均无效。

## 修正边界

引擎初始化时写入本次输出路径专属的 PID 回执，最终指标也记录 OS.get_process_id。Python 每五秒只采样该实际 PID，报告同时保留 launcher_pid／engine_pid，每条驻留内存样本带 PID。回执缺失、路径不符、最终 PID 不符、混入其它进程或没有有效实际引擎样本均拒绝通过；启动前短暂的空样本可保留，不回退采样启动器。既有时长、两轮热身、动作覆盖、内存漂移、ERROR 和退出泄漏门禁保持。生命周期 CI 明确检出 PR 头（手动运行取所选 ref），避免把隐式合并提交当作指定源码的证据。

原超时处理也只 kill 启动器，可能留下引擎。本批 Windows 超时／异常清理以本次 Popen 的父 PID 结束完整进程树；已结束的进程不再发停止命令。Linux 正常单引擎进程路径保持。

独立审阅分支仅修改长跑夹具、工具、测试和文档，没有更改生产游戏函数。三批设置／音频／存档组合另在冻结分支验证，不把这些未合并改动重复包装成本工具的实现。

## 已完成的协议证据

- 18 项工具测试通过，覆盖回执绑定、部分写入、非法 PID、启动器冒充、无实际样本、最终身份一致性及 Windows／Unix 停止边界。
- Windows 真实受控父子进程：原 launcher-only 处理留下子进程，新进程树处理清理两者。旧行为实验留下的自有子进程已立即清理，不以结束无关进程代替验证。
- 完整三轮短探针暂时恢复启动器采样时，21 次切区、3 次死亡、63 次界面开关及音频／最终孤立节点检查都完成，但新工具准确因引擎 PID 不符拒绝通过。随后按 SHA256 恢复正式源码。该短探针不是三十分钟验收。
- 当前三批组合默认清单保留全部 215 套。六套原生检查通过：设置 89、音频 108、来源备份 111、物品 243（同步解码 0）、六区 504 和音频退休；最终资源导入两遍通过。
