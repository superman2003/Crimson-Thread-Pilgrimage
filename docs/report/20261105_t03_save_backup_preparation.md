# T03：预备已保存来源备份，复用相同存档文件

基于 main `9ed0d619`（已含 #539 物品图集预热）。切区最后的发布阶段仍同步写存档，原协议中的备份复制、验证和替换会占用主线程。本批把**已经持久化的来源存档**备份交给一个有界后台任务，目的地状态继续在原有不让出帧的发布边界保存。主控制器的 `_publish_region`、奖励与区域发布顺序不改。

## 持久化边界

- 验证证明与写入授权分开。最多保留 16 个已验证文件摘要；只有真实读取／恢复仍会取得原有 reader lease。写入者可以准备自己已成功保存的来源备份，但不会因此得到新的写入权限。源字节变化、缺失证明、禁止写盘或注入写入失败时不启动新备份任务。
- 每个加载器最多一个后台任务，使用独占的私有暂存文件。工作线程只接收来源路径和已验证摘要，复制、复核后维护来源 `.bak`，不接收目的地进度，也不写主存档。取消期间来源备份维护可以完成；回滚在发布前逐帧等候该任务，整个宿主退出才会 join。
- 进程内存档写入、恢复及后台备份使用同一互斥锁，避免复制句柄或较晚完成的备份覆盖新的上一代。外部写入仍由原有来源摘要／reader lease 检查约束，最后安装前额外复核主存档；不把进程内互斥称作跨进程文件锁。
- 普通写入仍完整验证候选、现有文件和实际临时文件，并保留备份失败、安装失败及损坏证据的处理。已有备份仅在原始 SHA256 相同且不是符号链接／同一文件对象时复用。主存档仅在已验证临时文件与当前主文件原始字节相同、来源仍未变化时保留原文件并清理临时副本；这种无变化保存会保留主文件时间。真实内容变化仍必须完成主文件替换。
- 证明摘要沿用原文字验证口径，文件复用另外检查原始字节，避免 BOM 等文本解码差异被当成字节相同。存档版本仍为 3，没有新增持久化字段或改变迁移／字段验证器。

## 验证范围

新专项覆盖实际线程、独占请求、原始来源／备份字节、重复写入路径阻断、复制损坏、较早和复制后的来源变化、同进程并发写入、16 项证明上限、原写入权限及恢复。真实 World 在备份等待时保留来源存档，构筑／设置按键不能打开目的地界面；分别取消和在任务运行时销毁宿主，确认不发布目的地，工作线程、暂存文件、加载画布、过渡 token 与音频所有者退出。

八套正式原生门禁通过：新专项 111 项、六区加载 504 项、候选写入 103 项、恢复 35 项、世界状态、准备预算 174 项、物品预热 243 项（同步解码 0）和排版 18 项。[逐项原生记录](../../artifacts/save_backup_preparation_v14/verification-native.json)。六区改后第二轮退出出现一次 ObjectDB warning，原始日志保留；新专项自身没有该 warning，尚不据此关闭整体退出／泄漏验收。

Windows 原生专项包含 111 项；符号链接和硬链接真实文件夹具另在 POSIX CI 执行，Windows 不调整链接权限。80ms／50ms 的受控阻塞只用于并发和退出验证，不能作为自然帧时间样本。完整原生、无头、反向和源保留证据收于 `artifacts/save_backup_preparation_v14/`。

三项恢复旧行为的反向实验各准确失败 2 项：强制重做相同备份、绕过复制字节复核、强制替换相同主文件。各自均为 111 项、无 SCRIPT ERROR，恢复原源码 SHA 后重新正向验证。[反向原始记录](../../artifacts/save_backup_preparation_v14/final-negative-verification.json)。

## 交替前后测量

Windows、Godot 4.6.1、NVIDIA RTX 5060 原生 GL，未改的六区 504 项夹具。以 main `9ed0d619` 与冻结代码 `f04df829` 交替执行“前→后→前→后”，每次新进程，期间没有并行本地测试或导入。每次临时切换两份生产源文件，随后恢复原始 SHA；没有通过删减区域、物品、UI 或回归断言缩短样本。[逐区原始数值](../../artifacts/save_backup_preparation_v14/metrics-comparison.json)。

- 第一轮六区发布 CPU 中位数 20.350ms→16.620ms；两区改后更慢，其中温室 22.724ms→31.984ms，保留该样本。
- 第二轮中位数 17.964ms→10.219ms；六区均低于同轮改前值。
- 两轮合计改前范围 16.517–31.571ms、改后 7.047–31.984ms。观测离散较大，不宣称每次切区都改善或长尾尖峰已消失。准备阶段如需实际备份，会增加逐帧等候；已有独立相同备份时跳过线程和额外等待。

早期未同步物品预热的诊断样本另外保留，其中曾出现 115.885ms 的旧发布尖峰；复测没有稳定复现，未用它计算改进幅度。细分诊断显示主要耗时在备份／主文件替换，字段验证约 0.1ms、既有文件验证约 0.6ms；这些诊断是定位证据，不替代上面的交替实验。

最终双轮导入后的四套无头回归通过：新专项 111、候选写入 103、目录边界 177、启动边界 1054，runner 明确退出 0；启动失败文本属于负向场景预期，不存在 SCRIPT ERROR 或 ERROR。[无头结果](../../artifacts/save_backup_preparation_v14/verification-headless.json)。

npm test、campaign、runner 与台账校验通过；严格资源导入两遍均无引擎错误（recovery mode 关闭编辑器插件，不代表插件行为验收）。默认回归由 main 的 212 套增至 213 套。受保护的主控制器、NPC／主角／界面、物品预热及区域数据与 main 相同，存档字段验证器、迁移及恢复算法主体保持。[源保留证明](../../artifacts/save_backup_preparation_v14/source-preservation.json)。

## 结论边界

本批把来源备份维护移出发布帧，并减少已验证相同文件的重复替换。原子目标提交和剩余文件系统操作仍会阻塞；加载墙钟等待也可能增加。测量只解释指定机器上的 CPU 作业，不代表总加载提速、稳定 FPS、当前组合长跑或完整自然流程验收。T03、T04、T05 继续 OPEN。
