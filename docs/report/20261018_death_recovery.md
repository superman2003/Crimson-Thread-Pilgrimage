# 死亡与找回：现有规则审计与后期远程找回（G02）

修订方案 G02 要求：定义遗留物、货币损失、二次死亡与容量恢复；提供安全找回点和后期远程找回手段；Boss 重试不能拖成反复刷资源。

## 现有规则（审计结论）

| 情况 | 行为 | 结论 |
|---|---|---|
| 一般死亡 | 身上碎钱的一半留在“归途结”，位置是最后一次站稳的安全地面（不在陷阱上）；能力、装备和材料都保留 | 已定义，合理 |
| 二次死亡 | 新的归途结替换旧的，旧结里的碎钱就此失去；死亡时的提示会说明这一点 | 已定义，与同类游戏一致 |
| Boss 战中死亡 | 归途结放在场外的检查点，也就是复活位置 | 重试不额外损失，不需要刷资源 |
| 跨区 | 归途结记录所在地区，只在该地区出现 | 正确 |
| 找回位置是否可达 | 进入新地区时，安全地面重置为该区到达点，不会沿用上一区的坐标 | 不会掉进墙里 |

缺少的只有方案说的“后期远程找回手段”。

## 新增：钟龛召回归途结

- 击败三位地区守门者之后，在任何钟龛安坐时，如果世上还留着归途结，会弹出确认框，询问是否召回。召回只能收回**六成**；亲自去取仍可全数收回，所以这是“方便换钱”的取舍。
- 不会自动发生：死亡复活不会触发；安坐时只是询问，默认焦点在“亲自去取”。打开地图、背包或设置都会关闭询问。
- 召回后归途结从世界上消失，结果写入存档。
- 实现集中在新文件 `death_recall.gd`；`main_level.gd` 只加了三处挂接（建立对话框、关闭遮罩、安坐后询问），并让地图、背包、设置的开关同样能关闭这个询问。

## 验证

- `world_death_cache_flush` 共 27 项、0 失败，在原有的真实死亡与复活流程之后接着检查：
  - 复活不会询问召回；击败三位守门者之前，安坐也不会询问。
  - 击败三位之后安坐会询问，并锁定游戏输入；默认焦点在“亲自去取”；文字写明六成的具体数目。
  - 拒绝后归途结保留；打开地图会关闭询问。
  - 确认后正好收回六成，归途结清除，控制权交还，结果写入磁盘。
  - 没有归途结时，安坐不再询问。
- 下列套件通过：`save_product`、`upgrade_integration`、`seal_acceptance`、`world_host`、`world_save_candidate`、`world_enemy_residency`、`world_coordinates`、`cartography`、`inventory_map`、`input_settings_regression`、`ui_world_integration`、`first_court_experience`、`world_resume_regression`、`boss_trial`、`world_interaction_safety`、`combat_resource_cycle`。
- 本机负载很高时，`world_death_cache_flush` 和 `upgrade_integration` 各出现过一次“15 秒内未完成世界载入”的超时，重跑都通过，与本批无关。

## 仍待验收

- “三位守门者”和“六成”是第一轮数值，要在完整流程里看是否合适（T04）。
- 方案提到的“容量恢复”在本作没有对应机制（没有会因死亡下降的容量），不做。
