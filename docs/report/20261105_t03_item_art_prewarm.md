# T03：收集物与背包物品图集进入后台预热

前往含新物品的地区，或到达时首次建立使用该图集的背包项，原先会在 `_collectible`／`append_inventory_item` 内同步解码物品大图。人物和主角图已预读，物品图仍会漏到这些不可分割的任务中。本批基于 main `4242f790` 处理这部分。

## 行为与资源范围

区域构建前，现有资源预热计划也逐项扫描目的地收集物、数量大于零的背包物品及碎钱图标。相同图集只请求一次，沿用每步操作上限、最多两个共享资源所有者及取消／退出回收规则；人物专用的推测预读不额外获取物品。零数量条目不占用无关图集。

物品选择和旧回退规则集中到同一描述解析入口，正式消费者继续使用原 AtlasTexture、裁切和显示尺寸。六张原物品图集与清单逐项核对 main 原始 blob／LFS SHA256，全部原字节保留，见[源保留证据](../../artifacts/item_art_prewarm/source-preservation.json)。加载器增加物品扫描数、图集数及路径的观测字段。

## 同机测量

Godot 4.6.1，Windows 原生 OpenGL，使用未改动的 `world_async_loading` 504 项六区夹具，每版各两个隔离新进程。完整分区数据与日志路径见[测量记录](../../artifacts/item_art_prewarm/metrics-comparison.json)。

- 苔钟庭 `append_inventory_item` 最重项：33.64–36.03ms → 0.46–0.61ms；到达提交最大 CPU 批次 34.52–36.05ms → 10.63–12.25ms。
- 黑曜巡礼道最重构建任务：31.70–36.27ms（收集物）→ 6.86–10.26ms（岩体）；物品解码不再是该区最大的构建项。
- 首区人物／物品预热的墙钟等待约 32–33ms → 133–134ms。这段逐帧让出主线程，包含新增图集的等待，不能记作总加载时间缩短。

这些数值是加载器内部 CPU 作业／批次耗时，未覆盖整帧呈现、GPU 或自然游玩。岩体、设置页、音频准备、发布阶段及最终整合帧时间继续验收。

## 验证

- [五套原生 GL 通过](../../artifacts/item_art_prewarm/verification-native.json)：新物品专项 243 项、未改六区异步加载 504 项、拾取账 174 项、原角色预热零同步 miss、界面排版 18 项。零数量过滤加入后，新专项与六区加载已按最终源码重跑。
- 新专项对六区 32 个实际收集物调用正式工厂，并核对全部 48 条原物品图和旧回退选择。56 个物品描述去重为六张图集，共享并发上限为二，物品消费者同步解码为零。另在实际 World 到达初庭时携带第六区物品，核对预热计划、背包纹理及库存保留；数量为零的第四区材料不额外预读。
- [反向实验](../../artifacts/item_art_prewarm/negative-verification.json)：临时跳过物品预热，243 项准确失败 29 项、出现六次同步解码、World 绑定结果为 false，无 SCRIPT ERROR；恢复相同源 SHA 后 243 项通过且绑定结果为 true。
- 最终专项[无头环境通过](../../artifacts/item_art_prewarm/final-headless-run.log)；原资源竞争与退出套件分别通过 626／4 项，Dummy 渲染器按既有规则使用内联读取。`npm test`、campaign、工作流契约及最终双轮资源导入通过。Windows runner 实际执行三项、平台跳过 32 项；发布头 Linux 完整结果另记。

默认回归在本分支由 210 增至 211，新专项同时进入现有资源所有权 CI 的 GL 与无头门禁。原生入口：`npm run test:item-art-native -- --engine <Godot 4.6.1>`。本项独立于尚在评审的 NPC 问候 PR；合并时两项默认回归都需保留。
