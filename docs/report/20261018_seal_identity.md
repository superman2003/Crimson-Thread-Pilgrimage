# 三契印的疗伤方式、切换残留与铭饰叠加审计

E01／C02／E03 子项。修订方案第 7 条指出：三个契印的疗伤参数完全相同（耗 60 绯线、回 1 格、0.8 秒），差异只在疗伤结束后的附加效果，要求“重审爆发疗伤、空中风险、打断与纹章疗伤方式，不能只增加回血倍率”。本批把疗伤做成契印身份的一部分，审计切换残留和全部铭饰组合，并修补一个练针架回能漏洞。

## 契印疗伤

数值都写在 `build_catalog.json`，玩家代码只读数据。

| 契印 | 消耗 | 回复 | 缝补时间 | 空中 | 被打断 | 取舍 |
|---|---:|---:|---:|---|---|---|
| 缝名（快缝） | 60 | 1 格 | 0.55 秒 | **可以** | 损失全部 | 最快，下落途中也能补一格 |
| 司铸（承力缝） | 80 | **2 格** | 1.15 秒 | 须落地 | **只损失一半** | 每格最便宜（40），但要找比敌人收招更长的空档 |
| 校录（校录缝） | **50** | 1 格 | 0.9 秒 | 须落地 | 损失全部 | 抵消它较慢的回能（×0.8），每次补线需要的普攻次数与缝名相同 |

- 原有的结束效果保留：缝名加速、司铸抗一次击退、校录延长盐记。疗伤说明写明真实消耗、回复量和是否须落地。
- “铜背扣”按各契印自身的缝补时间加 15%。
- HUD 显示的中断损失和缝补时间改为按契印计算。
- 空中缝补只开放给“短时间、回一格”的轻型契印，数据校验会拒绝任何违反这一点的配置。
- 司铸的 1.15 秒超过多数小怪 1.1–1.2 秒的收招，这是有意为之：回两格要承担更大的风险，不能在每个收招空档里白拿两格。

## 练针架回能漏洞

练针架被当作敌人处理，每击都给绯线，倒地后又会复位，所以可以在练习房无限补满绯线，再带去打真正的战斗。这违反了修订方案“练习区资源不能带走刷取”的要求。

现在玩家会记录从练针架得到、尚未花掉的绯线（`practice_energy`）。离开所有练针架 520 像素后，扣回仍未花掉的部分。已经在练习中花掉的不会重复扣。真实敌人给的绯线不受影响。钟龛本来就会补满，所以这条规则只影响“把练习得来的绯线带去战斗”。

## 契印目录校验

`tools/validate_seal_catalog.py` 在 main 上已经失败：它还在检查“钟龛免费补给”，而战具早已改为付费补给。本批把它改为现行规则，并接入 `npm run test:campaign`，让很多 CI workflow 都会跑到：

- 战具补给须花费碎钱和材料，说明文字写明真实价格。
- 三个契印的疗伤方式互不相同。
- 一次疗伤的消耗不超过满条绯线，每格消耗不少于 40。
- 疗伤说明写明真实消耗与回复量。
- 只有短时、回一格的契印可以空中缝补。

## 验证

新增 `seal_identity`，共 1084 项、0 失败，已加入默认 CI，也可用 `npm run test:seal-identity` 单独运行：

- **疗伤**（真实 Player，伤害开启）：
  - 三个契印的消耗、回复和时间都来自各自的目录行。
  - 用真实按键在地面完成疗伤。
  - 缝名在下落途中开始并完成缝补，落地前就回满。司铸和校录在空中时，HUD 与实际动作都拒绝，也不扣绯线。
  - 受伤打断时按契印的损失比例退还。
  - 铜背扣按各自时间加 15%。
- **切换残留**：
  - 缝补中切换契印，按旧契印的规则结算，不会完成也不会刷新疗伤。
  - 线势和疗伤增益不会带到司铸，钟压和敌人身上的旧盐记在切到校录时清除。
  - 切换后立即使用新契印的疗伤规则。
- **铭饰叠加审计**：逐一枚举三个契印各自能合法装备的所有铭饰组合，检查以下每一项：
  - 每击回能在 12–30 之间。
  - 每格疗伤不少于 40 绯线。
  - 精准防御从不退还绯线。
  - 没有组合能让疗伤变成瞬发，或让技能更便宜。
  - 各项倍率都在 0.5–1.5 之间。
  - 一次疗伤至少需要两次普攻来补线。
  - 同一铭饰不能重复装备。
- **练针架**：用真实普攻打练针架，得到的绯线会被记录；离开后只扣回未花掉的部分；真实敌人给的绯线保留。

受影响的回归中，下列套件通过：

- 契印类：`build_system`、`seal_system`、`seal_combat`、`seal_ui`、`seal_acceptance`、`seal_acquisition`、`seal_presentation`。
- 战斗与动作类：`combat_resource_cycle`、`melee_recovery`、`player_upgrade_regression`、`first_court_experience`、`combat`、`player_motion_continuity`、`hero_animation`、`player_melee_feedback`。
- 构筑、存档与界面类：`upgrade_integration`、`save_product`、`ui_build_accessibility`、`build_slots`、`build_transaction_runtime`、`ui_world_integration`。
- `build_slots_ui` 在无头模式截图时会触发假渲染器错误，这在运行器说明里有记载。本机在真实 GL 下直接运行，30 项、0 失败。

旧断言的调整：

- `build_system` 原本断言三契印疗伤数值相同，改为断言各自来自目录。
- `combat_resource_cycle` 原本把 60、0.80 秒和“全额损失”写死，改为按契印的真实数值检查；HUD 测试也改为证明界面显示的是各契印自己的数值。

`npm test`、`npm run test:campaign`、recovery-mode 双导入均通过。

## 仍待验收

- 数值是第二轮，没有经过实际手感测试：司铸的风险窗口是否过大、缝名空中补血是否过强，都要在伤害开启的实际战斗中调整（T04）。
- 契印专属的普攻、下劈与疗伤动作（V02）需要新的美术资源。
- 线术技能的冷却与线量限制重审（C03），本批没有改动。
