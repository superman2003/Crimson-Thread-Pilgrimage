# 地图上的捷径状态与总览图钉防重叠（U04 子项）

修订方案 U04 要求地图显示“动态门／捷径状态”，台账则把“动态图层／楼层”和“总览图钉重叠”列为仍未完成。本批完成前两项，并说明“楼层”为何没有实现。

## 捷径状态（动态门）

六个区域各有一条拉杆捷径（例如钟舌库拉杆接通西环与前厅）。此前它们在区域地图和世界总览上都不显示，玩家无从知道哪条捷径已经接通。

- `survey_map_knowledge.gd` 新增 `shortcut_records`。拉杆所在房间已补绘时，地图上画出捷径标记：
  - 未接通：`⊣`，暗色，提示文字为“捷径未接通，拉杆在此：A ⇄ B”。
  - 接通后：`⇆`，金色，提示文字为“捷径已接通：A ⇄ B”。
  - 显示规则与已有的危险、能力门相同：未购或未补绘的房间不会泄露。
- 区域地图读当前区的实时接通状态；世界总览读各区存档里的状态，当前区仍读实时状态。
- 图例加入“⇆/⊣ 捷径”。

## 总览图钉防重叠

世界总览的缩放比例很小，相邻房间甚至相邻区域的图钉会投影到几乎同一点，编号互相压住。

- 每个图钉标签在元数据中保存真实投影锚点（`map_anchor`）。
- 锚点相距不到 24 像素的图钉归为一组，按各标签的实际字宽排成一排，以组中心为中线展开。
- 单独的图钉仍在精确的投影位置。区域地图和世界总览使用同一规则。
- 字宽用标签自己的字体测量：新建的 Label 还没有排版，`get_minimum_size()` 会返回 0。初版就是因此在实拍中仍然重叠，改为字体测量后修正。

## 楼层：没有实现，需要先定义

数据中没有“楼层”的概念：房间的 `depth` 是路线顺序，不是竖直层级。各区确实有房间矩形互相重叠（第二区有 37 对），但在手绘地图上，房间轮廓由真实碰撞地形绘制，重叠的矩形不会造成误读。台账与修订方案都没有定义“楼层”是什么，本批不凭猜测实现。如果它指的是“同一位置上下叠放、需要切换显示的房间”，需要先在数据里标出这类房间。

## 验证

- `survey_map_knowledge` 共 31 项、0 失败。新增：
  - 纯规则：未购不显示；未接通为 `⊣`，提示写出两端房间名；接通后为 `⇆`。
  - 防重叠：三个两位数图钉挤在同一点时展开且互不重叠，均在锚点 64 像素以内；用真实字体测得字宽；单独的图钉位置不变。
  - 正式 World：区域地图拉杆标记从 `⊣` 变为 `⇆`，图例有说明，世界总览读到该区的接通状态。
- `map_player_pins`：原有断言要求标签恰好在投影位置，现改为“锚点恰好在投影位置，标签离锚点不超过 64 像素”。其余断言原样保留，并通过。
- 以下套件也通过：`cartography`、`world_map`、`inventory_map`、`input_settings_regression`、`story_guidance`、`world_route_access`、`ui_world_integration`。
- 真实 GL 实拍在 `artifacts/map_dynamic_doors/`，由 `tools/capture_map_dynamic_doors.gd` 生成：
  - 苔钟庭拉杆接通前后的区域地图。
  - 世界总览上三个相邻图钉展开显示。
  - 这是夹具：直接授予购图和补绘，不是自然探索。
