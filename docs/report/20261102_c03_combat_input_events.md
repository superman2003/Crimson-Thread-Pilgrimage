# C03／U06：键鼠与手柄的每个战斗动作都从真实输入事件走到游戏状态

2026-11-02。台账 C03 的下一验收交付是“键鼠/手柄完整施放与打断验收”。现有测试多用 `Input.action_press` 直接按动作名，或只检查绑定表与按键提示文字；没有测试把**物理按键、鼠标按钮、手柄按键/扳机/摇杆**作为输入事件送进引擎，再确认玩家真的出了招。绑定写错（例如扳机轴方向、死区、遗留的旧键）在这些测试里都看不出来。

## 做法

新套件 `combat_input_events`。在正式 World 宿主（构筑快捷键只在 World 开放）的苔钟庭第一个钟龛起步，移除敌人；为了测输入通路，预先给齐全部能力与两个技能槽、两个战具槽（取得流程由各路线套件负责）。每个动作：

1. 复位玩家（原地站稳、满线、清冷却；测治疗时少一格血）；
2. 用 `Input.parse_input_event` 送入默认设备事件（与真实设备经过同一条 InputMap 路径），按住 8 帧后送松开事件；
3. 检查该事件确实属于该动作，且玩家/构筑状态发生了对应变化。

| 动作 | 键盘 | 鼠标／手柄 | 判定 |
|---|---|---|---|
| 普攻 | J | 鼠标左键、X | `attack_timer` 开始且不是掷钩 |
| 掷钩 | K | RB | 掷钩出手或抓取开始 |
| 跳跃 | Space | A | 向上速度 |
| 冲刺 | Shift | B | `dash_timer` 开始 |
| 线术技能 | L | Y | 绯线被消耗 |
| 钟挡 | Q | 十字左 | `guard_timer` 开始 |
| 治疗 | H | LB | 开始引导治疗 |
| 灯相位 | E | 十字右 | 相位开启 |
| 冠鸣 | R | 十字上 | 冷却开始且耗线 |
| 使用战具 | T | 十字下 | 战具总数减少 |
| 切换技能 | C | LT 扳机 | 当前技能槽改变 |
| 切换战具 | G | RT 扳机 | 当前战具槽改变 |
| 左右移动 | A／D | 左摇杆 | 水平速度方向 |

另外三项：

- **打断**：E 按住开启的灯相位在松开 E 后结束；LB 开始的治疗被一次受击打断，治疗没有完成、生命确实下降。
- **重映射**：打开设置，经正式捕获流程（同样用输入事件）把普攻从 J 改到 U：U 能出招、J 不再出招、手柄 X 照常可用；结束时用同一流程改回 J，临时偏好文件删除。

## 结果

32 个输入用例、66 项检查全部通过；本机约 35 秒。本批没有发现绑定错误，套件作为回归网：今后任一默认绑定、扳机轴、死区或重映射保存写错，都会在这里以“某设备的某动作不再改变游戏状态”失败。

## 边界

- 事件由引擎输入路径注入，不是物理设备；不同手柄的按钮编号映射（SDL 数据库）不在测试范围内。
- 只测默认绑定与一次键盘重映射；全部动作的全设备重映射组合由 UI 绑定套件覆盖文字与保存。
- 能力与构筑是预先给齐的，不代表取得顺序；手感与时机仍需人工试玩。
