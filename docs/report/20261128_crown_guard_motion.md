# 王座前廊守门：行为与动作第一轮

实机看到的问题不是“帧数不够”：普通近战的跟进／后撤逻辑被用在一段很窄的守门坡顶，丢目标归位时又把朝向强制改回右。实例 E14 的轮波和盾反仍按原条件、判定、前摇和收招运行；只给 E14 明确的守门站位：最多离岗位短步向前 26px，面对玩家站住，不在短距离内来回倒退；脱战回到原岗位不重置朝向。其他敌人不继承这条行为规则。

回声水轮骑士增加两套各六张独立绘制的转身／制动中间帧，加上进入时的原姿势。使用现有动画过渡和地面马达，没有改旧主图、受击和攻防判定，没有用透明叠影或整图缩放替代动作。转身 0.18s，停步 0.16s；攻击仍可打断纯展示过渡。两套由可选独立清单装入，与原角色资源一同预热。素材使用 OpenAI 内置图像生成；同时保留两轮底图检验，含未通过边界检查的停步版本。注册后核对每套六张不同图，画布透明、位置和体积在技术检查范围内。

云桌面 Godot 4.6.1：从同一门前存档靠近、退出、再接敌。守卫保持在坡顶一带，没再随玩家退回凹处；仍看到盾反命中，玩家从 6 格降到 4 格，正常击败后碎钱 560→568，正常保存退出。实机使用软件 GL 与 Dummy 音频；这不是实听，也不是全种类观感签收。回归：原行为有三条复现失败，修正后战术 303 项通过，动作中断／过渡 75 项通过。

后续分别验证铸雨渠水轮骑士和苔钟庭幼虫的脚底滑动、近距离朝向与攻后接走；再覆盖空中敌的无故反向、Boss 各阶段的预警和收招衔接。按敌人职责选站位规则，不能给所有单位复制守门逻辑。
