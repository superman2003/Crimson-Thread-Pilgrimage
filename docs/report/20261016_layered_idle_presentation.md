# 分层待机披风循环：固定身体与双脚

## 范围与依赖

基于镜头 PR #92 `5f4fd13b0c6cb307a65cd7172c4a620f3bfaacd4`，本批仅增加待机呈现层，不改变移动、攻击判定、治疗、存档或镜头算法。保留原 SpriteFrames 和动画状态；进入待机时使用一张固定身体/双脚/持剑图，另播放七个不同的真实披风区域。离开待机立即恢复原动作素材。

这是 A02/V02/V04 的一个有界子项。完整待机呼吸、跑步左右腿交替补帧、所有动作衔接及用户最终视觉验收仍 OPEN；不把七张披风图称为七张全身动作帧。此前仅修整体足锚注册不足以解决源姿态轮廓抖动，本批不沿用“待机漂移已完全修好”的表述。

## 素材与运行时

两个 PNG 均保持原 imagegen 输出字节，透明区域和原画布保留。固定身体 SHA-256 为 `2f596483024a92aa621929ab40766088ae7e1ec657d653e5301284d8c775dc30`，披风 atlas 为 `222d12909c41bdf26c19b5a4362aca9376140cfae0aca1a8a3be378cc0baf706`。atlas 共八格，仅按 `[1,3,2,4,5,6,7]` 使用七格，源格0剔除。每格100ms，循环0.7秒；区域RGBA哈希各不相同。没有复制身体导出假帧，没有图像插值、脚本重绘或逐帧缩放。

身体固定底部注册到原v3平均足底280；披风仅通过元数据统一挂点。左右朝向整体镜像，原四帧待机offset不作用于新身体。独立循环时钟沿用引擎delta、原动画播放倍率和暂停状态，不被旧0.4秒动画循环重置。

既有受击shader会覆盖输入COLOR；仅将旧sprite透明不能可靠隐藏原图。因此待机期间把同一个实时材质对象用于分层节点，旧sprite暂用默认材质遮罩；动作变化或helper移除同步恢复原材质/透明度/父材质设置。未改shader自身行为。坏manifest在修改原sprite前拒绝，原图可见；移除helper后不能在后续姿态同步中重新遮住原图。

## 已知限制与早期失败

新树最初未完整hydrate既有LFS贴图，导入曾出现Not a PNG；补齐后一次导入因XDG_CONFIG_HOME遗漏及180秒超时未通过。随后四个XDG目录独立、缓存正常，两轮严格导入通过。首次GL因Xvfb不在PATH未启动，无headless回退。第一次实际GL又发现合法JSON数值数组与整数常量数组直接比较不等，误拒合法manifest；现先验证数值再逐项比较，保留坏输入拒绝。上述失败不计通过。

软件GL驱动报告不支持V-Sync模式切换警告；不以固定60Hz模拟冒充实际渲染FPS。逐帧像素/状态检查不替代自然游玩、完整美术验收或实体手柄触感。

## 真实Player画面检查与仍未接受项

两个生产Player在独立物理空间接受同一组普通Input，真实地面、相同初始位置，没有免伤/授予物品或替换控制器。检查镜头固定2倍，只为比较像素，不代表生产镜头验收。左右朝向均有超过3秒零输入；384个连续实际渲染帧保留，视频23.815秒，逐帧PTS和原wall-clock误差不超过0.5ms。未插帧或变速。

最小范围接受：固定足底/身体、完整七帧披风顺序和真实首尾相邻帧、双向镜像/领口附着、遮旧源/动作恢复以及材质闪白。**新idle与v3跑步、普攻和落地之间仍有可见的一帧线条锐度、人物细节及披风轮廓切换，跨动作美术验收未通过。** 不把此缺陷降格为已解决，也不声称完整呼吸或全部动作素材已完成。此次重采集下引擎FPS中位20、范围2–24，不是目标硬件性能结果。
