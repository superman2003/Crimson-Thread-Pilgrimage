# 长时生命周期验证

目标是发现六区回访后的持续资源增长、旧敌人残留、音频未释放及退出错误。此工具使用正式 World、异步区域替换、真实敌人死亡、实际界面和正常死亡重生链。旅行与靠近敌人使用明确的位置夹具，战斗阶段开启无敌以保证重复性，死亡阶段关闭无敌并接受致命伤；这不是自然路线、经济、难度或陌生玩家验收。

## 运行

使用 Godot 4.6.1，先按项目既有流程水合 `godot/assets/**` 并完成严格双轮导入。在 Linux 上安装 Xvfb 与 Mesa，再执行：

```sh
python tools/run_runtime_soak.py --engine /path/to/godot --seconds 1800 --log-dir /new/path/soak
```

Windows 或有真实桌面的机器加 `--native-gl`；窗口置于屏幕外，声音使用 Dummy 后端，仍创建并推进实际原生音频播放对象。默认 Linux 使用真实软件 GL，没有无头纹理后端替代。每次使用新的日志目录，测试存档由临时目录独立创建和清理。

两轮完整六区热身后开始计时；每轮走过六区、开关地图/背包/设置、打开一位已加载 NPC 的未读完文字、驱动敌人 AI/真实攻击/击败，再在第六区接受致命伤并由正常计时器重生，最后回到第一区同一入口取样。每轮七次异步区域替换；结束前释放正式 World 和过场音频。`--seconds 1` 仍会跑两轮热身与一轮测量，但报告明确标为短探针，绝不能当作三十分钟证据。

## 证据与门禁

保存精确 Git revision、Godot 版本、完整命令、生产源文件内容哈希、原始引擎日志、逐轮指标及每五秒的进程驻留内存。测量静态内存、纹理内存、节点/资源、孤立节点、真实 SFX/UI 播放器、音乐与字幕书签，并记录包括切区在内的完整帧间隔直方图和最大值。纹理计数为零的平台只能标为不可用；它不是显卡总占用或显卡驱动的预算。进程 RSS 和 Godot 静态内存分别呈现，不混用。

在首次三十分钟运行前固定以下诊断上限：同一区域热身后静态内存净增长不超过 64 MiB，至少三个样本的最小二乘增长斜率不超过 1 MiB/分钟。两项分别防止突然留存和缓慢漂移，不代表目标机器的整体内存预算。节点/资源的绝对值保留供归因；热身后孤立节点不得增加，最终不得留有测试拥有的孤立节点。旧区域敌人的弱引用必须全部失效，六区音乐书签必须存在且最多八条，字幕最多六十四条，实际 SFX/UI 声部最多二十四，最终所有已观察原生音频资源必须释放。

退出码、ERROR/SCRIPT ERROR、未完成标记、缺少动作或时长、源文件变化、内存漂移、退出泄漏均令验证失败。已有失败证据保留，不通过修改阈值或重跑抹掉。真实渲染帧间隔包含加载压力和机器其他负载，不能直接声称目标硬件帧率或玩家舒适度达标。

GitHub 的 `Runtime lifecycle soak` 在改动本工具的 PR 上运行短探针，手动触发默认测量三十分钟。长时本机报告及具体问题另记在升级台账。
