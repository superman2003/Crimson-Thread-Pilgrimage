# W00 剩余部分：共享物理洞口与相邻区域驻留（分阶段方案）

2026-11-15。只是方案，不改代码。W00 剩下的三项里，这份方案覆盖“共享物理洞口”和“相邻完整区域驻留”。“真实帧时间与长期稳定”要在 Windows 真机上验收，放在最后一阶段。

## 现在的结构

| 方面 | 现状 | 位置 |
|---|---|---|
| 世界坐标 | 六区的原点和尺寸固定，区与区之间留有 1220–1680 像素的空隙 | `data/world_layout.json`、`world_coordinates.gd` |
| 跨区连接 | 五条实体通道铺在空隙里，把六区连成一张网 | `data/world_passages.json`、`world_passage.gd` |
| 持久宿主 | `main_level` 本身就代表“当前区”：148 个脚本变量里，除 `SESSION_FIELDS` 列出的 22 个，其余 126 个每次换区都用反射重置成默认值 | `loader_region_state.gd:104` |
| 区域节点 | 区域拥有的节点直接挂在宿主下面，使用区域本地坐标。玩家也在本地坐标里模拟 | `loader_budgeted_prepare.gd:206` |
| 过通道 | 冻结并隐藏源区的所有子节点，玩家切到通道专用碰撞层走管道。走到终点再请求分帧加载器（预检 → 卸载 → 构建 → 提交，可以取消和回滚） | `world_passage.gd:122–420` |
| 区内流式 | 已有：地形画面分块、平台驻留、NPC/存档点/交互物驻留、敌人挂起、岩体几何缓存、出生平台缓存 | `world_platform_residency.gd`、`world_gameplay_residency.gd`、`chapter_terrain.gd` |
| 邻区预取 | 已有：配置、贴图、落点附近的几何（最多 12 块平台、6 个岩体块），以及少量敌人/NPC 预实例化。都处于脱离状态，**不进入源区物理** | `world_prefetch.gd`、`world_gameplay_prefetch.gd` |

可以利用的余量：玩家速度 285 像素/秒，最短的空隙也要走 4 秒以上。上一次测量里，分帧提交尾段的墙钟时间是 0.6–1.0 秒（`docs/report/20261013_budgeted_region_commit.md`）。所以只要构建能在玩家走路时进行，管道本身就足够遮住整次重建。

## 难点

1. **宿主即当前区**。区域状态散落在 126 个宿主变量上，HUD、地图、音频、房间镜头也都只认一个 `config.id`，没法让两个区同时“活着”。
2. **本地坐标**。两个区的本地坐标会互相重叠，不能直接放进同一个物理空间。
3. **加载时冻结宿主**。加载器构建期间宿主停用、玩家不能动。无缝驻留则要求构建时玩家照常行走。
4. **有状态对象的归属**。敌人、门、守门者、奖励和存档点都按区记账，跨区时归属不能出现模糊的一刻。
5. **预算**。两区同时驻留会让节点数、碰撞体和内存增加，目前没有测量过。

## 关键选择（最初的建议；坐标、区域状态、邻区外壳三项已在“阶段 2 之后的做法修正”里改掉）

| 问题 | 建议 | 不选的方案及原因 |
|---|---|---|
| 坐标 | **当前区保持在本地原点，邻区按两区原点差平移后放置；跨过交接线时整体平移一次原点（rebase）。** 现有代码里所有拿玩家位置与配置坐标比较的地方都不用改。 | 全部改成世界坐标：要改动几百处位置比较和全部验证，风险高。 |
| 区域状态 | **把区域变量逐组搬进 `RegionState` 对象，宿主通过 `host.region` 访问当前区。** 已有的反射重置列表正好可以当搬迁清单。 | 用影子宿主构建再移植：构建代码会碰到玩家、存档、UI 和音频这些会话对象，影子很难做到干净隔离。 |
| 邻区里有什么 | **只放“外壳”：开口附近窗口里的地形碰撞、平台和画面。没有敌人、NPC 和可交互物。** | 两区完整同时运行：预算翻倍，归属问题也最多。 |
| 何时交接 | **管道中点设一条交接线，越过它才切换当前区；交接前往回走等于取消。** | 进管道就切换：玩家回头时要反向重建，来回抖动的代价高。 |
| 存档 | 管道内照旧不能存档；交接前存档点仍记在源区，交接后才落到目的区。存档格式不变。 | — |
| 快速旅行、读档、复活 | 保留现在的整区加载路径，不纳入无缝范围。 | — |

## 分阶段

每个阶段单独一个 PR、单独一条台账。前五个阶段都保留“走到终点整区加载”作为回退，任何一阶段失败都能停下而不留半成品。

### 阶段 0：盘点与量尺（不改行为）——已完成

- 卸载规则本身就定义了归属：宿主下除玩家和通道以外的子节点都属于当前区。新验证 `world_residency_inventory` 检查换区后树根和玩家下面都没有多出节点，敌人和守门者都挂在区域子节点下面。
- 126 个会重置的宿主变量写成分组清单 `godot/scripts/region_state.gd`。宿主新增或删除变量而清单没跟上时，验证会失败。
- 验证同时记录每区规模和每个通道口的外壳规模。

**结果**（无头环境，固定出生点，经同步换区夹具到达各区）：

| 分组 | 字段数 | 去向 |
|---|---:|---|
| 区域节点（地形、岩体、平台、门、守门者等） | 17 | `RegionState` |
| 区域运行状态（配置、计数、房间、出生点等） | 38 | `RegionState` |
| 界面（HUD、对话、行囊、地图、设置、愿板） | 33 | 改为会话级，换区不再重建 |
| 音频 | 6 | 改为会话级 |
| 进度（物品、能力、货币、剧情标记等） | 14 | 改为会话级（现在每次换区先清空，再从存档恢复） |
| 静态数据 | 3 | 改为会话级缓存 |
| 换区控制 | 15 | 留在加载器/宿主 |

验证确认：界面每次换区都被整套重建；8 个进度值换区前后不变，只是被清空后又恢复了一遍。也就是说，阶段 2 里一半以上的字段（界面、音频、进度）不是搬进 `RegionState`，而是提升为会话级，这一步反而会省掉每次换区的重建。

| 区域 | 区域节点 | 碰撞形状 | 贴图（估算） |
|---|---:|---:|---:|
| 苔钟庭 | 1214 | 203 | 47 MB |
| 铸雨渠 | 1161 | 189 | 47 MB |
| 盐白书库 | 910 | 136 | 47 MB |
| 断弦温室 | 871 | 147 | 48 MB |
| 黑曜巡礼路 | 837 | 125 | 48 MB |
| 无声王冠 | 884 | 185 | 47 MB |

出口附近 2560×1800 的窗口里（玩家站在入口、按正常到达流程预热后），驻留的碰撞形状有 10–102 个，占本区的 8%–65%。苔钟庭的钟管口占 50%，盐白书库的军用运书廊口占 65%。所以外壳并不总是一小块：阶段 3 不能固定用这个窗口，要改成按开口所在的房间来取，并对每个出口设上限。

### 阶段 1：区域容器

- 区域拥有的节点改挂在一个 `RegionRoot`（Node2D，位置为零）下面，不再直接挂在宿主下。卸载变成释放一个容器的内容；过通道时冻结也只需停用这个容器。
- 实际改动面比最初估计的大，所以拆成三个 PR：
  - **1a（已完成）**：新增 `level_host.gd`，生产代码改为通过它取关卡宿主（37 个文件）。原先有三类写法默认“父节点就是宿主”：敌人、特效等把 `get_parent()` 当关卡来调用；用 `x.get_parent() == level` 判断归属；在宿主上按名字找区域节点。这三类都改成同时兼容两种挂法。其中第一类原本用 `has_method` 兜底，节点挪走后会悄悄失效，不会报错，所以必须先改。这一步不改变任何行为：容器还是空的，辅助函数只是退回原来的写法。
  - **1b（已完成）**：验证和工具里 123 个文件、308 处直接在宿主上按名字取节点或遍历子节点的写法，改为走 `level_host.gd`。同样不改变行为。
  - **1c（已完成）**：宿主在启动时创建常驻的 `Region` 容器，关卡构建代码里 36 处往宿主挂区域节点的地方改为挂进容器。卸载时释放容器里的节点，容器本身保留。
    - 过通道时仍然逐个冻结区域节点，不冻结容器本身：容器是常驻的，冻住以后到达的新区域会跟着停用、不可见。“冻结一个容器”留到阶段 4 双缓冲时再做。
    - 玩家、通道，以及由玩家一侧生成的特效仍直接挂在宿主下。
    - 绘制顺序的变化：容器排在玩家之前，所以同一层级（z_index 相同）的区域节点现在始终画在玩家下面。以前只有首次加载是这样；换区之后区域节点是后挂的，反而画在玩家上面。
- **验收**：每个 PR 都跑全部回归；`world_async_loading` 的取消/退树边界不变；同步构建和分帧构建的结果仍然一致。

### 阶段 2 之后的做法修正（2026-11-15）

做完阶段 0 和阶段 1 以后，根据实测，后面几个阶段改成更简单的做法：

| 原计划 | 现在的做法 | 原因 |
|---|---|---|
| 把区域变量搬进 `RegionState` 对象，宿主通过 `host.region.xxx` 访问 | 变量留在宿主上，`region_state.gd` 把区域那一组字段整体取出和放回 | 这些字段在生产代码里被引用约 2500 次、验证里约 4800 次，逐个改名的改动面太大 |
| 界面、音频提升为会话级，换区不再重建 | 界面和音频跟着区域一起切换，目的区的界面在玩家走管道时提前建好 | 界面的每个子系统（购图、图钉、死亡回收、钟龛回程等）都按“全新构建”写成，改成原地重绑要逐个重写 |
| 邻区按原点差平移放置，交接时整体平移一次原点 | 目的区直接在本地坐标里隐藏着构建，交接时只换玩家坐标，与现在到终点时相同 | 静态地形和平台停用后仍留在物理里，但玩家走管道时只和管道碰撞，两区几何重叠不影响玩家；敌人、交互等停用后会从物理中移除 |
| 邻区外壳（开口附近的只读碰撞和画面） | 取消 | 区与区之间隔着 1220 像素以上的管道，在源区看不到邻区；进了管道以后，目的区在走到中点前就已经完整建好 |

### 阶段 2：区域状态——已完成

- 新增 `region_state.gd`：列出属于“一个驻留区域”的 94 个宿主字段（区域节点 17、区域运行状态 38、界面 33、音频 6），提供取出、放回、清空、切换四个操作。
- 换区重置时，这一组字段改由它来清空，结果与原来的反射重置完全一样。
- `world_residency_inventory` 新增检查：取出后清空，宿主上这组字段等于脚本默认值，进度字段不受影响；放回后每个字段都恢复原样。

### 阶段 3：隐藏着构建目的区

- 加载器增加一种模式：源区保持原状，目的区构建进第二个停用且隐藏的容器。每批构建作业开始前把宿主的区域字段切到目的区那一组，作业结束后切回源区那一组。仍按 2ms 分帧。
- 构建期间不碰玩家：出生定位、镜头、音频绑定、存档和奖励都留到交接时再做。
- 取消时只需丢弃第二个容器和它的字段组，不需要恢复源区快照。
- **验收**：隐藏构建的结果与现有构建逐项一致；在构建的任意一帧取消，源区的节点和字段都不变；构建期间源区照常运行一帧不出错。

### 阶段 4：管道内交接（试点：排水钟管）

1. 进管道：源区照旧冻结，同时开始隐藏构建目的区。
2. 构建完成并且玩家越过管道中点：分帧卸载源区（此后不能再取消回源区）。
3. 卸载完成：交接。放上目的区的字段组，显示并启用它的容器，把玩家和管道换算到目的区的本地坐标，绑定音频、镜头和存档，发放到达奖励。全程不出现加载遮罩。
4. 如果玩家走到终点时交接还没完成，就在终点等待（现有的管道端帽挡住），并统计等待次数和时长。
- 中点之前往回走等于取消：丢弃目的区，源区解冻，与现在相同。
- 交接帧不能再拆分，要单独计时并设上限。
- **验收**：真实输入双向走钟管，全程没有加载遮罩；交接帧耗时单独记录；中点前回头不留任何目的区状态；交接后回头会开始一次反向的隐藏构建；奖励、存档和地图只记一次。

### 阶段 5：推广到其余四条通道

- 运书泵廊、旧军用运书廊、冠脊石道、根须影管逐条替换。能力门（攀壁、双线跃、灯影相位）仍在通道入口检查。
- **验收**：每条通道各自通过阶段 4 的整套验收；`world_passage_network` 从“到终点加载”改成“全程无遮罩”。

### 阶段 6：洞口连续与收尾

- 进管道时源区不再隐藏：保留画面，只停用玩法，让管道口与房间在视觉上连起来。
- 删除通道专用的终点加载路径（快速旅行、读档和复活继续使用整区加载）。
- **验收**：五条通道的入口、中段、出口像素检查通过，入口处能看到来时的房间。

### 阶段 7：真机验收

- 在 Windows 真机上做长跑：六区来回走多轮，检查交接帧耗时、内存曲线和 ObjectDB 泄漏。这一项同时满足 T03 的长跑要求。
- **验收**：真机数据入库，W00 状态行勾掉“共享物理洞口”和“相邻完整区域驻留”。

## 风险

| 风险 | 应对 |
|---|---|
| 隐藏构建时，构建作业读到的是源区的东西（例如按分组查敌人） | 阶段 3 逐个审查构建作业；验证里比较隐藏构建与普通构建的结果，并检查源区字段和节点在构建前后不变 |
| 两区的静态几何在同一坐标重叠 | 交接前先卸完源区；交接之前玩家只在管道碰撞层上 |
| 玩家走得比构建和卸载快 | 在终点等待，并统计等待次数和时长；先在最短的钟管上试点 |
| 隐藏构建让节点数和贴图内存接近翻倍（每区约 840–1210 个节点、约 47 MB 贴图） | 阶段 3 记录峰值；只在管道内同时持有两区，交接后立即卸载源区 |
| 无头环境的数字不代表真实帧时间 | 每个阶段的耗时只作为同环境下的前后对比；绝对数字以阶段 7 的真机数据为准 |

## 不在范围内

- 区域之间新增通道，或者改动区域布局。
- 快速旅行、读档、复活改成无缝。
- 邻区敌人跨区追击。
