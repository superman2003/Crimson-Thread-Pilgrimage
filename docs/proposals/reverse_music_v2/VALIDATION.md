## 方法与明确限制

1. FFprobe 检查采样率/声道；FFmpeg 解码为 float32 PCM 后计数，所有首尾排除样本范围 `[0, N)` 与 manifest 一致。CH02/04 理论乐拍长不能精确表达为整数样本，终点使用最近样本舍入，误差小于半个样本。
2. 样本峰值由解码 PCM 得到。真峰值用 SciPy `resample_poly` 四倍过采样估计，计算时拼入循环前后各 256 帧，避免把边界当零填充；所有曲目都低于 -3 dBTP。报告另存 FFmpeg `loudnorm` 的输入 true peak 作为交叉参考。四倍估计不能替代所有硬件重构滤波器。
3. LUFS-I / LRA 使用 FFmpeg `loudnorm` 的 EBU R128 输入测量；不是把 RMS 冒充 LUFS。另记录 RMS、峰均比和 100 ms RMS 窗 P90–P10 动态。LRA 在 32–45 秒短片与大量留白中只供参考，CH06 大 LRA 是稀疏句法的结果。没有强行把每曲压成同一动态。
4. 循环接缝差值为 `max(abs(first_frame - last_frame))`，并与全曲内部逐样本差分 P99 比较。技术门限为 `step < max(0.006, 4 * P99)`；这个相对门限筛查突兀采样跳变，不能证明没有音乐节奏断裂、尾音变化或编曲不自然。所有曲目的接缝差值小于内部差分 P99，最大约 0.005581（满幅比例）。
5. 每首尾音以 modulo overlap-add 回卷，反射也为 circular delay；生成器未做整曲首尾淡出。接缝两侧 20 ms RMS、实际峰值、差值及哈希均见机器报告。Vorbis 编码后重新测量，而不是只检测编码前 WAV。
6. 技术检查还包含：全部数值有限、每曲小于 350,000 字节、全部文件合计小于 4,000,000 字节、双声道、48 kHz、精确解码帧数，以及综合响度距目标小于 0.5 LU。没有执行或修改游戏运行验证、CI 或任何既有测试。

## 重建环境

- Python 3.12.14
- NumPy 2.3.5
- SciPy 1.17.0
- ffmpeg version 6.1.1-3ubuntu5 Copyright (c) 2000-2023 the FFmpeg developers
- 命令：`python tools/proposals/reverse_music_v2/build.py`
- 全部音符与随机 seed：同目录 `score_events.json`
- 每曲完整检测值与 SHA-256：同目录 `validation.json`

## 重建一致性

同一环境连续完整运行固定 serial 的生成器两次，12/12 个 OGG 的 SHA-256 完全一致。见 `rebuild_verification.json`。另检查 manifest 的 12 项顺序、每区探索/Boss 等采样长度与分句对齐、相对路径和 OggS 文件头。
