## 文件与查看

入口是 `assets/proposals/reverse_scenery_v2/manifest.json`。`file` 与 `preview` 均相对该目录。每区三层 `chXX_far.svg`、`chXX_mid.svg`、`chXX_front.svg` 可独立开关。`chXX_preview.png` 仅合成三层美术，没有伪造玩家、敌人或实机关卡截屏。

- far：有意不透明，提供完整底色。推荐 z=-30、parallax=0.15。
- mid：透明、设施主体 alpha=0.82。推荐 z=-20、parallax=0.40。
- 实际关卡及角色：位于中景和前景之间；本提案不创建这一层。
- front：透明、仅边角。推荐 z=20、parallax=0.75。中央 `(160,100,640,390)` 的 alpha 全为零；这是画幅内静态留白，不是摄像机运动后的遮挡承诺。

全部 `horizontal_tiling=false`。请逐房间布置单幅面板；不可开启 repeat、镜像平铺或将图形轮廓生成碰撞体。视差数值是起始建议，需由实际房间尺度/镜头范围确定。前景如随镜头移动，必须重新检查屏幕安全区；必要时固定至房间镜头或隐藏。

## 明暗预算

亮度值采用 sRGB 通道加权近似 `(0.2126R+0.7152G+0.0722B)/255`，不是线性光度或 WCAG 对比比值。对有覆盖像素统计：远景 p95≤0.32、中景 p95≤0.52、前景 p95≤0.44；中景画幅覆盖≤25%，前景覆盖≤12%。具体配色、实测 p95 和覆盖率写在 manifest 的每层中。高亮细线主要靠两侧，上部大构图和下部留空保留深度。不要把统计阈值称作实际游戏战斗可读性测试。

## 生成与验证

从仓库根目录：

```sh
python tools/proposals/reverse_scenery_v2/build_pack.py
python tools/proposals/reverse_scenery_v2/validate_pack.py --godot /path/to/godot
```

依赖 Python 3.10+、Pillow、numpy、Inkscape CLI；只有第二条的 `--godot` 可选。固定 seed=260614，随机性只用于低亮度细尘；主体设施为代码定义的原创矢量路径。同一依赖版本下输出逐字节复现；跨渲染器版本 PNG 压缩/抗锯齿可能不同。

已用 Inkscape 和 Godot 4.6.1 检查：18 个 SVG XML、960×540 viewBox、局部引用、18 次扩大画布后的无外溢检查、6 个 PNG 解码/体积、前景安全区、Godot 原生 `Image.load_svg_from_string` 18/18 有效且中景非空。初版 mask 在 Godot 不兼容，最终已全部去除；文件只用基本几何、分组、渐变及 clipPath，无 mask/filter/字体/远端资源/嵌入位图。画框边缘对柱、根、管作有意裁切，结构内部可延展至画框外；验证的是裁切后的可见 bounds。

`render_report.json` 和 `validation_report.json` 记录结果。六区合成均经目视检查：区域设施可区分、没有地面替身、边角前景不侵入中央动作留白。未验收实际关卡中的镜头视差、碰撞、性能、导航、玩法或动态遮挡。SVG 原生栅格化通过不等于已接入运行场景。
